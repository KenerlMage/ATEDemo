# 《机器常数》Runner 侧需求（SR02）

> 来源：`controller/机器常数功能模块.md`（同一份需求设计的 Runner 章节抽取，保持与 Controller 备份同源）
> 目录约定：Runner `docs/需求设计/` 为统一查阅入口；Controller 工程内 `docs/需求设计/` 保留规范备份。
> 格式：SR/AR 两级，每个需求三字段（需求价值 ≤50 字、设计目标 ≤100 字、需求描述 ≤200 字）。

## 一、范围

本文件只收 Runner 执行侧需求（SR02）。Controller 侧的归档、审批、编排见 `controller/机器常数功能模块.md`。

## 二、需求清单

### SR02 机器常数在 Runner 的标定与执行（Runner）

【需求价值】标定结果在执行端闭环：能写入、能清除、能校验、能人工确认后再回传 MES。
【设计目标】Runner 支持常数读写与范围校验、单用例人工确认门禁、标定类标识，并提供上位机与下位机两种标定 Demo。
【需求描述】TPS 清单新增机器常数字段与解析方案；执行端提供常数写入、清除与范围校验；单条用例可设 manual check 属性，人工确认后才回传机器常数与测角结果；标定类用例显示标识；标定支持 Windows 本机与 Linux 下位机两种方案。

#### SR02-AR01 TPS 机器常数字段与解析方案

【需求价值】TPS 能声明所需常数及其解析方式，执行端无需硬编码。
【设计目标】TPS 清单可声明常数模型引用与解析器，Runner 按声明解析出可写入的常数集合。
【需求描述】清单新增 `machine_constants` 段，含模型键、别名、解析器类型（xml 契约、kdb 查询、python 回调）与解析参数；解析器输出统一为字段键到值的映射与单位；解析失败给出精确错误位置；旧版 TPS 无该段时按空集合处理。

#### SR02-AR02 常数写入与清除

【需求价值】标定结果与默认值切换无需手工改文件，减少错写。
【设计目标】提供一次写入与一次清除两套能力，操作可批量、可回滚、有审计。
【需求描述】写入按 TPS 声明把常数集合落到目标 `Module.xml` 或 `<SN>_Module.xml` 并生成结果文件；清除将目标模型恢复为默认值或删除该 SN 的标定实例；两者支持按模型、按字段选择范围；每次操作记录操作人、时间、前后值、来源 TPS 与任务号。

#### SR02-AR03 常数值范围校验

【需求价值】超范围的标定值直接拦截，防止错误常数进入后续测试。
【设计目标】写入前逐字段校验范围与单位，越界即拒绝并定位到字段。
【需求描述】按模型定义的上下限、单位、枚举取值校验；越界或单位不符时拒绝整次写入并列出全部违规字段（键、值、允许范围、来源）；支持配置为警告放行并标记；校验结果写入执行记录。

#### SR02-AR04 单用例 manual check 与回传门禁

【需求价值】关键结果由人确认后才回传 MES，避免自动误判流出。
【设计目标】单条用例可设 manual check，确认后机器常数与测角结果才回传，界面同步产生确认按钮。
【需求描述】用例新增 `manual_check` 属性（布尔、可指定复核角色、可指定需确认字段）；执行到该步后暂停，界面显示确认按钮，确认或带理由驳回；未确认的结果滞留本地并标记待确认；确认后一次性回传机器常数与测角结果到 MES，回传失败可重试且不重复。

#### SR02-AR05 标定类用例差异化标识

【需求价值】执行端能快速识别标定步骤，避免与生产结果混淆。
【设计目标】标定类用例在步骤列表、执行面板、结果报告中均带统一标识。
【需求描述】用例或 TPS 声明标定类型后，步骤行显示「标定」徽标、执行面板顶部显示标定模式条、结果报告单独分区；标识与 Controller 侧 TPS 清单标识同一套图标与配色；标识不影响执行顺序。

#### SR02-AR06 Windows 本机标定 Demo

【需求价值】验证上位机直接标定链路，作为标准标定 TPS 的最小可运行样例。
【设计目标】提供一条可运行 Demo，用 python 程序或人工输入填值并生成带 SN 的标定结果文件。
【需求描述】Demo TPS 关联 1 个模型，步骤含 python 程序填值与人工输入两条路径；填值完成后生成 `<SN>_Module.xml`，默认值被实测值替换并附标定时间与操作人；结果文件可被 AR01 解析器读回校验。

#### SR02-AR07 下位机 Linux 标定 Demo

【需求价值】覆盖下位机已部署另一套系统的现场，标定数据从下位机数据库取出。
【设计目标】通过 paramiko 远程登录目标机，查询其数据库标定清单，生成一个或多个常数文件并回传 PC。
【需求描述】目标机连接信息（主机、端口、账号、密钥或口令）取自装备属性配置；paramiko 登录后执行只读查询取得标定数据清单；按清单生成一个或多个常数文件并回传 PC，再走 AR02 写入；连接失败、查询超时、数据缺失分别给出明确错误，不静默降级。

#### SR02-AR08 下位机连接配置

【需求价值】下位机地址与凭据集中管理，避免散落在用例脚本里。
【设计目标】装备属性配置中可维护下位机连接项，Runner 与 Demo 统一取用。
【需求描述】在装备属性配置新增下位机连接项，含主机、端口、用户名、认证方式（密钥、口令）、数据库类型与查询语句模板；凭据加密存储且界面上不明文回显；连通性测试按钮给出往返时延；配置随装备包下发与备份。

#### SR02-AR09 下位机返回数据映射

【需求价值】下位机字段与模型字段口径不同，需要一处可维护的映射。
【设计目标】提供字段映射表，把下位机查询结果稳定映射到模型字段与单位。
【需求描述】映射表在 Controller 随模型维护，含下位机字段名、模型字段键、单位换算系数、缺省值策略；映射缺失时报错并指出未映射字段；单位换算可逆，回传时按原口径还原。

## 五、未覆盖范围

- 结果报告未把标定结果单独分区（`/tasks/{id}/calib` 已提供分区数据）。
- 写入/清除未落审计表，也未记录前后值，仅在 XML 的 Calibration 节点留操作人/任务号。
- 真实 Linux 下位机成功取数未联调，失败路径为真实 socket 验证、成功路径为单测打桩。
- 跨进程并发写同一 `<SN>_Module.xml` 未压测。
