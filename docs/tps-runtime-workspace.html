TPS 运行环境 · workspace / 公共 conftest / driver 配置

TPS 不再直接跑在 testresource/ 里：运行时复制一份临时副本到安装目录下的 workspace/<TPS 名称>/run_<任务号>/，装备信息、测试阈值与设备 driver 全部由程序提供的公共 conftest.py 注入，而 driver 配置由测试台注册结果投影到 SQLite 供运行时读取。

1. 一图看懂：一次 TPS 运行发生了什么

① 读清单 tps_runtime.read_tps() 读 testresource/spm_rh_dyn/tps.json（v2 目录包）或单文件 JSON（v1 旧格式兼容），校验三个主要字段。
② 建运行环境 stage() 确保 workspace/ 与公共 conftest.py 就绪（不存在则创建/部署）→ 把整个 TPS 复制一份临时副本到 workspace/SPM读头动态测试/run_df0d1b653f88/ → 生成执行入口 test_tps_generated.py 与运行环境文件 ate_env.json。
③ 配测试台 按清单里的 bench.preset_id 自动匹配已注册测试台（也可用 bench_id 指定），把测试台标题/编号、运行模式写进 ate_env.json；没有测试台时如实提示，不阻塞仿真运行。
④ 逐步骤执行 每个步骤在临时副本目录里跑 pytest <节点> -v（cwd = 运行目录）。公共 conftest 提供 ate_ctx 等夹具：从 SQLite 取装备与 driver、从清单取阈值。
⑤ 判定与落盘 用例返回值经清单 checks 映射到 testconfig 阈值自动判定，越限即失败；结果写入 run_result.json（汇总 / 逐用例 / 阈值明细 / 每台设备解析出的 driver），HTML 报告新增「运行环境 (workspace)」卡片。

能力实现
自动创建workspace_root() 取 <ATE>/workspace；ensure_workspace() 缺失即建；后端启动挂载与 /api/runtime/workspace/init 都会确保就绪

公共 conftest 升级版本一致 → kept；版本变化 → 自动备份旧文件后覆盖，并同步到新运行目录

3. 公共 conftest.py 注入什么

装备信息 ate_bench / ate_devices

从 SQLite 的 bench_registry / device_registry 读出本次测试台与设备（IP·端口·串口·波特率·资源地址 + 解析出的 driver 规格）。

  • TPS 里不写死任何地址
  • 现场改址只需改注册库 / 装备属性配置页
  • 无测试台时给出明确提示（可继续仿真）

测试阈值 ate_thresholds · ctx.check()

本次 TPS 的 testconfig 子字典整体注入；用例只需回传测量值，上下限判定与中文提示由 conftest 完成。

  • 越限抛 LimitError，带阈值明细
  • 改阈值只改清单，不动用例代码
  • 结果里保留 实测值 / 下限 / 上限 / 单位

设备 driver driver(别名) / command(别名, 动作)

按 device_config 别名 → 注册库设备 → 工厂解析出具体 driver（示波器 / 万用表 / 电源 / 电子负载 / 信号源 / 运动控制 / 夹具），统一返回 {ok, value, detail}。

  • 仿真与真机共用同一驱动，只在传输层分叉
  • 未识别设备走通用 SCPI 或被动设备规格
  • 用例结束统一释放连接

结果记录 ate_runner

pytest 钩子在会话结束/用例失败时兜底写盘，异常中断也不会丢结果。

  • 逐用例写 run_result.json（续写同一任务）
  • 失败用例带阈值明细与测量值
  • 记录每台设备的 driver 规格，便于归因

4. TPS 三个主要字段

字段作用示例
testconfig 测试用例的阈值设置（测试套中单个用例的阈值上下限子字典） {"TC_VDD": {"label": "读头上电电压", "min": 3.135, "max": 3.465, "unit": "V"}}
device_config 测试用例使用的设备信息子字典（别名 → 注册库设备 / 角色） {"scope": {"device_id": "rh-scope"}, "dmm": {"role": "万用表"}}
cmd_suit 测试套排列子字典，其中每一个测试用例对应 testcase/ 中提供的一个实现 [{"no": 1, "id": "TC001", "name": "读头上电电压", "case": "testcase.power::power_on_voltage", "checks": {"VDD": "TC_VDD"}}]

展开成执行步骤

setup(SETUP01) → cmd_suit(TC001 TC002 TC003 TC004 TC005) → teardown(TD01)
= 7 个顺序 pytest 节点：test_tps_generated.py::test_setup[SETUP01] / ::test_case[TC001] … / ::test_teardown[TD01]

用例签名

def 用例(ctx, **params) -> None | float | dict

  • 返回 float：按清单 checks 第一个键判定
  • 返回 dict：{检查项: 值} 逐项映射到 testconfig
  • 返回 None：只做动作（初始化/终止类）

清单校验（中文错误清单）

  • 阈值上下限非数字 / 下限大于上限
  • cmd_suit 引用了未定义的阈值
  • case 不是 模块::函数 形式、id 重复
  • 与旧 steps 字段混用

5. 设备 driver 配置为什么放 SQLite

注册即入库

第三步注册完成（或设备属性 PATCH 改址）后，_save_registry() 把注册库全量投影到 SQLite；注册库 JSON 仍是唯一事实源。

运行时只读 SQLite

公共 conftest 从 SQLite 取设备，而不是让每个 TPS 自己写 IP/端口；现场改址 TPS 代码零改动。

可随时重建

SQLite 只是投影：删库后 POST /api/runtime/db/sync（或重启后端）即从 JSON 重建，不影响授权与注册数据。

驱动工厂

drivers/factory.py 的 DRIVER_SPECS 按厂商/型号/类别/接口打分选驱动，先具体（泰克 MSO5 示波器）后兜底（通用 SCPI），未识别设备走被动设备规格。
