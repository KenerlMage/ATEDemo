④设备驱动层 把“动作名”翻译成各家命令：差异全部收在这里

驱动工厂 drivers/factory
按设备档案字段（型号 / 厂商 / 类别 / 接口）打分选驱动：先具体（如某系列示波器）→ 再类别（万用表/电源/负载/信号源/运动控制）→ 最后通用 SCPI 兜底
驱动实现 drivers/scope·scpi
统一动作接口 do(action, **params) -> {ok, value, detail}：示波器 / DMM / PSU / 电子负载 / AWG / 运动控制 / 被动设备
传输层 drivers/transport
Socket（LAN/SCPI）· Serial（RS232/485）· Simulate（无硬件同构）；真机与仿真只在这一层分叉
另有标准化驱动 SDK：sdk/ate_drivers（冻结契约 api 1.2）面向驱动开发者/厂商
api.Scope（通用顶层方法）→ family/scope.ScopeDriver（动作语义·单位·测量算法·波形结构）→ vendors/<厂商>/driver.py（只填差异面：命令表 / 前导字段 / 枚举映射 / 仿真模型 + MODELS 型号派发）→ driver.json 清单；kit/cli·conformance 负责骨架生成与上架门禁。
⑤ SCPI / 串口帧（VISA · socket · 仿真）

⑤仪器与链路 现场资产：地址、型号、序列号只存在于设备档案

测试仪器
示波器 · 数字万用表 · 可编程电源 · 电子负载 · 信号源/波形发生器 · 运动控制盒 · 被动夹具（仅登记）
接入方式
LAN（SCPI over socket）· 串口（RS232/485）· 仿真后端（离线联调/产线培训）
层谁写只依赖不写什么（关键约束）
测试平台平台开发TPS 清单（只读元数据）+ 注册库不写死仪器型号 / 站点地址 / 判断阈值
TPS 包（tps.json）测试开发 / 装备工程别名 + 阈值键 + 用例引用不写 SCPI、不写 IP/串口号、不写连接管理
测试用例 testcase/*.py测试开发上下文契约 ctx不 import 驱动实现、不 sleep 等采集、不自己开关仪器
驱动层平台 / 仪器组设备档案（SQLite）+ 传输层不含阈值、不含测试流程、不写报表格式
传输 / 仪器现场 / 厂商——
数据流（谁给谁）
① UUT + task_id → ate_env.json（本次运行环境）
② 测试台 + 设备连接参数 → ate.db（device_registry / bench_registry）
③ 阈值 → TPS 的 testconfig（不在平台、不在驱动）
④ 测量值 + 判定明细 → run_result.json → 平台汇总成报告 / 回 MES
为什么是 pytest
每个 TPS 步骤 = 一次 pytest <node id> 调用；配置、驱动、阈值全部由公共 conftest.py 注入。 于是测试用例只表达“测什么 + 限值多少”，平台统一负责“怎么跑、怎么记、怎么中断”。
与原始描述的对应
TPS 文件夹里的配置文件，当前实现是 tps.json（清单）+ ate_env.json（本次运行环境，含 UUT 号）；UUT 属性档案另由 /api/uut/{sn} 或 uut_profiles.json 提供。若你们的规范确定叫 uut.json，可在 tps_runtime 里加一层文件名兼容即可。
