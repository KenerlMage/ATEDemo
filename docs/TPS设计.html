一份受控基线清单，四个角色各司其职

uut.json 不替用例写逻辑，也不替报告定结构。它只做四件别处做不了的事： 说明跑哪些用例与顺序、给出判据预置值、校验 PN 适配范围、绑定实际台架。 判定挪进用例、用例名取自 docstring、连接参数来自 SQLite——cmd_suit 因此瘦到 3 个必需字段。

四个角色，各自只干一件事

判据只有一条：任何信息只允许有一个事实源。谁能表达得最准确，就归谁。

清单层uut.json
用例基线（跑哪些、什么顺序）· PN 适配校验 · 台架绑定 · 判据预置值
不写用例逻辑、用例名、判定映射、连接参数、报告结构
用例层testcase/*.py
业务动作 · 自我判定 ctx.expect("键", 值) · 产出测量值与判定明细
不关心执行顺序、超时、重试、在哪个通道跑
注入层conftest.py
环境 / 装备 / 驱动 / 阈值注入 · run_case 执行与记录 · 会话收尾释放设备
不写任何具体判据值
执行层main.py + tps_runtime
校验 → 生成入口 → 逐条拉起 pytest 进程 → 汇总 → 报告 → 落库
不解释业务语义
存储层ate.db
test_records 固定条目落库 · device_registry 提供连接参数
不承载明细数据
运行时数据流

判定
用例内 ctx.expect(键, 实测值) 自查 → 明细留痕

02

承载边界：什么进 uut.json

判据一句话：只有"与用例业务逻辑无关、且与实际台架或本批 PN 有关"的配置才进 uut.json。

内容进？放哪理由
跑哪些用例、执行顺序进baseline.cmd_suit编排语义，用例代码无从知道
超时 / 重试 / 失败策略 / 条件跳过进exec / skip_when运行策略，属编排；用例不该自己重试
判据预置值（min / max / std）进testconfig随批次与 PN 调整，需工程师评审，不能埋进代码
设备种类与别名进bench.device_config与业务逻辑无关，只与实际台架有关
PN 批次号 / SN 规则 / 通道结构进adaptation本 TPS 的适配范围，运行前校验
用例实现引用 module::function进cmd_suit[].case1:1 映射的唯一锚点
用例名、描述、标签、默认参数不进docstring / marker用例自身属性，写两遍必然漂移
测量值与阈值的对应关系不进ctx.expect判定逻辑属业务，随用例走
设备连接参数（IP / 端口 / 串口）不进SQLite device_registry换台架即变，写进受控文件就是灾难
报告 / 记录字段不进用例产出 + 固定记录R1/R2 是固定条目，uut.json 无权定义
03

判定链路：从"清单映射"到"用例自查"

旧 · 废弃

清单决定判什么，用例决定测什么

用例 return {"VDD": 3.31}
  └─► _apply_checks
        按 cmd_suit.checks {"VDD":"TC_VDD"} 映射
          └─► ctx.check("TC_VDD", 3.31)

判定归属碎在两边：改一个参数化用例要在两个文件之间来回改。

新 · 采用

用例自查，conftest 只提供判据

v = ctx.command("dmm","measure_dc_voltage")
ctx.expect("TC_VDD", v)     # 判定 + 留痕
  └─► ctx.take_checks()
        └─► 明细进 run_result.json

conftest 需加 _pending_checks 与 take_checks()， 并升 ATECONFTEST_VERSION 2 → 3，否则现场不会更新。

连带影响 · 必须一起做

移除 checks 会让现网唯一的跨字段校验失效

现在 validate_v2 会拦下"引用了未定义阈值"——那正是靠 checks 实现的。 删掉它，错误就从"导入时拦下"退化成"运行时 KeyError"。所以必须补一条静态扫描： 读 testcase/*.py 里 ctx.expect("KEY" / ctx.check("KEY" 的字面量， 校验 KEY 已在 testconfig 定义。这条校验要先于 checks 的移除上线。

04

cmd_suit 收敛结果：3 个必需 + 4 个可选

字段必需作用为什么留下 / 为什么删掉
id必需报告主键、parametrize 用例 id、结果续写键现网 record() / _upsert() 全靠它
case必需module::function 引用run_case 用它 _load_callable，1:1 映射锚点
params必需调用实参 fn(ctx, **params)现网调用契约；只放数值，别名从 ctx 取
exec可选timeout_s / retry / on_fail编排策略。因每条用例是独立进程，实现位置在 Runner 侧
parallel可选per_channel / shared并行调度信息，默认值不写
skip_when可选条件跳过（设备缺失等）替代旧 optional，语义唯一
resources可选并行时的仪器占用声明需与 slots.resource_bindings 一致校验
checks ↓删除原：测量字段 → 阈值键的映射判定改由用例 ctx.expect 完成；报告由用例产出
name / description / no / tags / optional / depends_on / kind ↓删除 原：用例名、描述、序号、标签、可跳过、依赖、类型 分别来自 docstring / marker / 数组顺序 / on_fail / 所在段落——全部是第二事实源

精简后的条目（这就是全部）

{ "id": "TC004",
  "case": "testcase.comm::playback_signal",
  "params": { "freq": 1000, "vpp": 2.4 },
  "exec": { "timeout_s": 40, "retry": { "max": 2, "interval_s": 1.0 } } }

硬标准：留下的每个字段，都能在 conftest 里指到真实读取它的那一行代码。

05

校验清单（8 条，其中 3 条是本次新增的关键）

#校验类型说明
1name 由必填降为可选调整用例名来自 docstring；若保留则加"与 docstring 不一致告警"
2checks 引用校验失效副作用移除 checks 后现网唯一跨字段校验消失
3静态扫描 ctx.expect / ctx.check 的键新增·关键补 #2 的空缺，防止退化为运行时 KeyError
4case 存在性（在 testcase/ 找到该函数）新增现在只校验字符串格式，函数写错要等运行时才炸
5清单 ↔ 目录双向一致新增引用不存在 → 报错；有用例未引用 → 提示
6testconfig 判据类型新增range 需 min 或 max；stats 需 std 且 k>0、n≥2
7adaptation 自洽新增批次正则能匹配 part_number；count 与 slots 一致；资源无重复占用
8device_config 跨表一致新增类别 / device_id 须在该测试台 BOM 内；fixture 须存在
