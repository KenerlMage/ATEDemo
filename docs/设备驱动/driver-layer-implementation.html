02契约：只描述用例会用的语义

契约是最贵的一层，改一次全公司回归，因此只收「跨型号稳定」的动作。

  • 9 个方法connect / close / identify / configure_timebase / configure_channel / configure_trigger / acquire / measure / describe。生命周期固定为「构造 → connect → 配置 → 采集/测量 → close」，close 之后任何操作必须抛 ScopeNotConnected。
  • 8 个测量项vpp / vmax / vmin / mean / rms / frequency / period / rise_time。量纲写死在契约：电压类为 V，频率 Hz，时间 s。未知测量项抛 ScopeUnsupported，不允许返回 None 或 NaN。
  • 返回结构波形用 t0_s + dt_s * i 表达时间轴，不使用厂商时间数组；不把厂商对象交给用例层。这样跨型号、跨厂商的数据可以直接比较与存档。
  • 异常层级ScopeError 下分 NotConnected / Timeout / Unsupported / DataError。驱动包负责把厂商库异常映射进来，运行时按类型决定重试或中止。

设计取舍：测量值默认从最近一次采集推算，而不是调仪器内部测量功能。代价是精度受采样率限制，收益是八项语义在所有型号上完全一致 —— 换型号不会让判定阈值漂移。需要仪器级精度时用 prefer_instrument_measure=True 显式切换，并在档案里记录。

代码视图：生命周期与厂商库边界

03示例包：R&S MXO 与 RsInstrument 的边界

RsInstrument 在本包里只承担一件事：把字符串与二进制块送进送出。它不承担版本管理、不承担档案解析、不承担重试策略。

// manifest.json 关键字段
{
  "name": "rohde-schwarz-mxo",
  "version": "1.2.0",
  "capability": "oscilloscope",
  "contract": "1.0",
  "runtime": { "runner": ">=1.6 <2.0", "python": ">=3.11" },
  "owner": "仪器驱动组",
  "entry": "rs_mxo.driver:RsMxoScope",
  "vendor_deps": ["RsInstrument==1.12.1"],
  "simulate": true,
  "verified_on_hardware": false
}
  • 延迟 importfrom RsInstrument import RsInstrument 写在 _open_rsinstrument() 内。构建机、CI、无库现场仍可跑仿真与契约测试，不会因为缺库而无法验证。
  • 不静默降级mode="hardware" 下缺库或连不上，抛 DriverUnavailable 并给出可执行提示；只有设备档案显式写 simulate 才走仿真。生产台上"以为在测真机、其实在跑假数据"是最高代价的故障。
  • 命令集中全部 SCPI 收在 scpi.py，5 处待核对的路径标 VERIFY。换型号只改这一处，CI 也能一眼确认命令拼接没有散落在业务逻辑里。
  • 仿真同路径仿真只替换 IO 层（write_str / query_str / query_bin_block），驱动逻辑一行不分叉。因此仿真通过能说明契约与解析正确，但不能替代真机核对 —— 这一点写在 manifest 里而不是只写在文档里。

04版本选择交给 lock，不交给代码

台型声明「要什么」，lock 记录「这台机器实际装了什么」，解析器负责两者一致。

// benches/BENCH-DEMO/bench.lock.json
{
  "bench": "BENCH-DEMO",
  "station_type": "scope-bench",
  "runner": "1.7.3",
  "resolved": [
    { "capability": "oscilloscope", "package": "rohde-schwarz-mxo",
      "version": "1.2.0", "tree_sha256": "d67a6b6a57f1…" }
  ],
  "locked_at": "2026-11-08T21:43:12+08:00"
}

解析时的四道校验，任一不过即拒绝加载：版本是否满足台型约束、目录哈希是否与 lock 一致、包实现的契约版本是否与平台一致、Runner 与 Python 版本是否在包声明范围内。安装与回滚只改 lock，不动平台。

实测到的一件事：把包内 CHANGELOG.md 改名后，lock 立即校验失败并拒绝加载。这不是误报 —— 目录内容确实变了，现场的"和研发一致"就此被破坏。宁可要求重新锁定，也不接受静默漂移。

05运行时：把柜内争用挡在包之外

  • 资源仲裁按仪器资源名加锁，一个柜挂多个测试站时，争用同一台仪器的操作排队而不是互相打断量程与触发状态。
  • 超时与重试建连按次数重试并记录事件；命令级失败映射为 ScopeTimeout，由上层决定中止还是重试，包内不写业务策略。
  • 拓扑快照describe() 汇总「能力 → 包@版本 → 资源名 → 模式 → 连接状态」，现场排障第一步看这里，不必翻日志。
  • 单进程单版本同一能力被要求两个版本时抛 VersionConflict。多台架并发走多进程，避免一个进程里混装两套解析结果。
