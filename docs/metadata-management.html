两个子页面各自解决什么

装备树管理

/metadata/tree
  • 新增 / 编辑 / 删除 产品 → 子系统 → 测试台类型 三级节点
  • 子系统可同时挂在多个产品下（如 SPM 属于 1000-A / 2000-B）
  • 新增类型时可从同子系统内 BOM 最全的类型复制一份，避免空白 BOM
  • 节点写入 tree/tree.json；列表显示每个类型的 BOM 设备数与被引用台数

测试台BOM管理

/metadata/bom
  • 参照「装备属性配置」中测试台 BOM 的口径：设备元信息 + 默认连接参数
  • 三级级联选定类型后，以行内编辑表格维护整张 BOM（增行 / 复制 / 排序 / 移除 / 删库）
  • 一并维护测试台属性：名称 / 类别 / 典型 DUT / 推荐节拍 / 描述
  • 「从设备模板库添加」可引用已有型号；保存写入 tree/bom/<类型编号>.json
  • 页面直接标出该 BOM 供「新建测试台」使用，并可一键跳到注册向导

二、数据流：谁读谁写

元数据管理页面（前端）
装备树管理 / 测试台BOM管理 → 全部写操作走 /api/metadata/*
▼ 保存（原子写：先写 .tmp 再替换）

backend/tree/tree.json（树与类型属性） + backend/tree/bom/<类型编号>.json（BOM 清单）
▼ load_presets() / load_meta()

/api/testbench/tree 级联选型 · /api/testbench/presets 类型与 BOM · /api/testbench/overview 指标

第一步选中类型 → 自动获取该类型 BOM；第二步按默认值预填设备配置；第三步注册并自检
▼ 注册落库
testresource/testbenches.json + backend/ate.db
已注册测试台各自保存一份设备配置副本；注册库投影到 SQLite，TPS 运行时由公共 conftest 读取 driver 配置
边界很清楚：BOM 只描述「该类型标准装备组成」。新建测试台时用它生成设备清单初值；现场在「装备属性配置」里改址只写该台测试台自己的记录，不回写 BOM；反过来改 BOM 也不会自动改写已注册测试台，但之后新建的测试台会立刻读到新版本。
原预设文件 testresource/testbench_presets.json 降级为种子 + 回退源：仅在 tree/ 首次建立时导入一次；若 tree/ 读取异常，注册流程自动回退到该文件，不因元数据异常而中断。

五、校验与保护

节点编号

  • 字母 / 数字开头，仅允许 字母 数字 . _ -（如 PB-PWR-02、DSP、3000-C）
  • 类型必须挂在「该产品下已声明」的子系统分支上，跨分支挂载会被拦下并提示
  • 编号唯一；改编号会同步迁移 BOM 文件与子系统内引用

BOM 条目

  • 设备名称 / 型号必填；同一张 BOM 内设备编号唯一
  • 网络设备：IP 或主机名格式 + 端口 1–65535；可编程设备必须有默认 IP + 端口
  • 串口设备：COMx / /dev/tty* + 波特率 300–921600；可编程设备必须有串口号

删除保护

  • 被已注册 / 草稿测试台引用的类型不可删除，提示引用台数
  • 产品还有子系统或类型、子系统下还有类型时不可删除

写入安全

  • 全部保存走「先写 .tmp 再 os.replace」的原子写
  • 进程内互斥锁串行化写操作；手工编辑 JSON 也无需重启（每次请求重新读取）

七、现场使用步骤

① 建树元数据管理 → 装备树管理：「＋ 新增产品」建产品；在产品行点「＋子系统」建子系统（可勾多个所属产品）。
② 建类型在子系统行点「＋类型」，填名称 / 类别 / 典型 DUT / 推荐节拍 / 描述；勾选「从同子系统内 BOM 最全的类型自动复制」，避免空白 BOM。
③ 编 BOM切到测试台BOM管理，三级级联选中该类型 → 核对属性 → 「＋ 新增设备行」或「从设备模板库添加」→ 填默认连接参数 → 「校验」→「保存 BOM 与属性」。
④ 用 BOM测试台导航 → 新增测试台：第一步选中该类型即带出这份 BOM，第二步按默认值预填后按现场改址，第三步注册并自检。
⑤ 回退需要恢复出厂元数据时，装备树管理页点「全量重建」（以预设文件为准，手工新增节点会丢失）。

八、已知边界

  • 不影响已注册测试台：改 BOM / 改属性不会同步到已注册测试台的配置副本；统一改址请到「装备属性配置」逐台修改（有格式校验与变更留痕）。
  • 类型编号重命名会迁移 BOM 文件并更新子系统内引用，但已注册测试台记录里的 preset_id 不会自动改写，需重新注册或手工改配。
  • BOM 表格为行内编辑、字段较宽，窄屏需横向滚动（表格设 min-width，避免卡片互相挤压）。
  • 预设文件不再被写入，仅作种子与回退源；若团队以该文件为发布物，请「全量重建」后再导出 tree/。
