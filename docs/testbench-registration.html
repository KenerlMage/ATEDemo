4. 三步注册流程

第一步 · 级联选型与工位 产品 → 子系统 → 测试台类型三级下拉，选中即获取该类型标准 BOM 清单；填写测试台名称、SPMTS 编号、产线、工位、物理位置、备注。此步可存草稿。
第二步 · 可编程设备配置 网口设备填 IP / 端口 / 协议 / VISA 资源串 / 通道；串口设备填串口号 + 波特率；USB / GPIB 填资源地址。实时显示「已配置 x/y 台」，支持回填 BOM 默认值，前端先拦地址冲突。
第三步 · 注册并验证 选择验证方式后提交注册，逐台探测设备连通性并输出自检清单；结果落库并保留最近 10 次历史。

5. 自检清单

类别检查项判定
配置类测试台编号格式（SPMTS + 12 位数字）不匹配即失败
配置类测试台名称已填写为空即失败
配置类产线 / 工位信息完整缺任一项即失败
配置类可编程设备配置完整网口缺 IP:端口、串口缺串口号、USB/GPIB 缺资源地址即失败
配置类设备地址无冲突同一 IP:端口 被多台设备占用即失败
配置类必备设备均已配置required 且程控设备未配置即失败
设备类每台设备 1 项连通性检查网口 TCP 连通 / 串口打开成功 / USB·GPIB·无接口则跳过并提示人工确认

整体结论：任一项失败 → fail；无失败但有跳过 → warn；全部通过 → pass。验证方式分「真实探测（real）」与「离线模拟（simulate，清单标注模拟）」，工位无仪器时也能演练全流程。

6. 接口

方法路径说明
GET/api/testbench/tree三级级联树：产品 → 子系统 → 预设测试台类型（级联下拉数据源）
GET/api/testbench/presets · /api/testbench/presets/{id}预设类型列表 / 含完整 BOM 的详情
GET/api/testbench/overview指标汇总（含产品数 / 子系统数）
GET/api/testbenches · /api/testbenches/{id}已注册测试台列表（带产品 / 子系统归属）/ 详情
POST/api/testbenches创建或更新（三步共用；status=registered 为正式注册）
DELETE/api/testbenches/{id}删除测试台
POST/api/testbenches/{id}/verify连通性自检（{"mode":"real"|"simulate"}）
POST/api/testbenches/restore-defaults重建默认测试台（幂等；已存在则返回“无需重建”）

7. 数据模型

testbench_presets.json（预设类型 + BOM，只读）
├── products[]    { id: "1000-A", name: "1000-A 机载电子系统" }
├── subsystems[]  { id: "SPM", name: "SPM 电源模块", products: ["1000-A","2000-B"] }
└── presets[]     { id, name, category,
                    product: "1000-A", subsystem: "SPM",
                    description, typical_dut, recommended_cycle,
                    bom[] { id, name, model, vendor, category, role, programmable,
                            interface, default_host, default_port, default_serial_port,
                            default_baudrate, default_address, protocol, required, note } }

testbenches.json（注册表，JSON 单文件 + 原子写）
├── id / preset_id / preset_name / title / serial / status(draft|registered)
├── station       { line, station, location, remark }        ← 已去掉班次/责任人/工号
├── devices[]     { id, name, model, vendor, interface, host, port,
│                   serial_port, baudrate, address, channel, programmable, configured }
├── verification  { overall, mode, checked_at, summary, checklist[], conclusion }
└── verify_history[]  最近 10 次自检摘要
   （接口返回时补 product / product_name / subsystem / subsystem_name → 该测试台服务的装备树分支）
