1. 界面结构（三栏切换）

页面顶部是一条栏位切换条（⚙ 装备属性配置 / ✓ 测试台装备自检 / ▤ 装备报告中心），三栏各自独立成块，切换时地址栏同步（#/equipment?tab=selfcheck、#/equipment?tab=reports），刷新后停留在同一栏，可直接分享链接。

栏位内容代码落点
⚙ 装备属性配置测试台切换标签 + 筛选/搜索 + 设备卡片网格（右键可编程设备改属性）；底部四个面板：待注册测试台（草稿清单 + 导出按钮）、已注册测试台（勾选 / 全选 + 导出选中 / 导出全部已注册）、TPS 运行环境、TPS 运行目录EquipmentView.vue
（同一路由内用 v-show 分栏，不新增导航项；右侧导航仅保留一个入口）
✓ 测试台装备自检目标测试台下拉 + 运行模式下拉（离线模拟 / 真实探测）+ 三个按钮：测试台装备初始化、测试台装备终止、测试台装备自检；执行后直接弹出报告
▤ 装备报告中心报告区（目录路径 / 已保存文件数 / 占用空间 / 打开本地资源管理器 / 刷新清单）+ 历史报告表（时间 / 类型 / 测试台 / 模式 / 结论 / 大小 / 操作，顶部按「全部 · 硬件自检 · 装备初始化 · 装备终止 · 测试台导出」过滤）
报告与导出弹窗报告弹窗内 <iframe> 直接渲染完整 HTML 报告，底部可「在资源管理器中定位」或「新窗口打开」；导出弹窗显示条数 / 范围 / 文件名 / 落盘路径，并可重新下载EquipmentView.vue + api.js

分栏状态存在地址栏 hash 查询串里，不落 localStorage：多个页面标签可各自停在不同栏位互不干扰。

2. 测试台导出（待注册 / 已注册）

导出把测试台的预设类型 / 工位 / 每台设备型号·接口·连接参数整体导出为 ate.testbench.export.v1 JSON，可用于备份现场配置、离线核对，或迁移到其他工控机。两个入口：

入口位置导出内容
待注册测试台导出「装备属性配置」栏 · 待注册测试台面板草稿状态（status=draft）测试台，按钮「导出待注册测试台」一次全导
已注册测试台导出「装备属性配置」栏 · 已注册测试台面板已注册（status=registered）测试台：可勾选多台后点「导出选中」，或直接「导出全部已注册」；支持「全选 / 清空选择」
① 组装读取注册库中符合范围（待注册 / 已注册 / 指定台 / 全部）的测试台，导出设备清单（型号 / 厂商 / 接口 / IP·端口 / 串口·波特率 / 资源地址 / 是否已配置）
② 落盘写入报告目录 logs/testbench/export_<范围>_<时间戳>.json（如 export_registered_… / export_selected_…），并登记报告清单
③ 下载与复核浏览器同时下载同一份 JSON；弹窗显示导出条数、状态构成（已注册 / 草稿）、作用范围、文件名与落盘路径，可「在资源管理器中定位」或「重新下载」

作用范围写在 scope 字段：pending（待注册）/ registered（已注册）/ all（全部含草稿）/ selected（指定台）；接口参数 status（registered / draft / all，缺省 = 待注册，兼容旧行为）与 bench_ids（指定台）。没匹配到测试台时也允许导出空清单（同样带 schema，便于线下按模板填写）；历史报告里的导出记录类型标签统一显示为「测试台导出」（旧记录无需数据迁移）。

3. 装备初始化 / 终止 / 自检

三个按钮都作用于所选测试台的全部设备，逐台按类别取标准动作序列并记录每条指令的执行结果。

设备类别初始化动作（示例）终止动作（示例）
示波器*RST → *CLS → 默认时基 TIM:SCAL → *IDN?STOP → SYST:LOC
数字万用表复位 → FUNC "VOLT:DC" → VOLT:DC:RANG:AUTO ON → *IDN?ABOR → SYST:LOC
可编程电源OUTP OFF → VOLT 0 → CURR 0.1（限流保护）输出关闭 → 电压归零 → 退回本地
电子负载INP OFF → FUNC CURR关闭输入 → 退回本地
信号源OUTP OFF → FUNC SIN关闭输出 → 退回本地
运动 / 转速控制盒串口握手 AT → 转速归零 SPD 0 → ID?转速归零 → 撤销使能 → 关闭串口会话
夹具 / 探针（非程控）标记为「信息项」并提示人工确认；不参与结论判定，不会把整体结果拉成“待人工确认”

两种运行模式

  • 离线模拟 只生成与真实流程同构的步骤记录，不向仪器发送任何指令；报告中标注“模拟”，测量与执行结果不冒充实测。
  • 真实探测 真正建链（LAN 建 TCP / 串口开 COM）并逐条下发指令、读回应答；点按钮前会二次确认。现场无仪器时如实记录失败原因（例如 连接失败: timed out），不会伪装成功。

结论判定

失败项 → 未通过；程控设备存在跳过项（缺动作模板 / 未装 pyserial）→ 待人工确认；其余 → 通过。

4. 界面显示自检报告

执行任一动作后自动弹出报告弹窗，弹窗内用 iframe 渲染后端生成的完整 HTML 报告（自包含、无外部依赖）：

  • 顶部：结论徽标（通过 / 待人工确认 / 未通过）+ 中文结论与“离线模拟 · 非真机实测”标注（模拟模式）；
  • 测试台信息卡：名称 / 编号 / 预设类型 / 状态 / 产线·工位 / 物理位置 / 设备规模；
  • 汇总数字：检查项 / 通过 / 失败 / 跳过（初始化与终止额外显示动作总数、成功数与耗时）；
  • 明细表：自检为「配置类 + 每设备连通性」逐项清单（含目标地址、状态、失败或跳过原因）；初始化 / 终止为每台设备的「动作 → 指令 → 结果 → 说明」逐条记录。

自检结果同时写回注册库（verification + 最近 10 次 verify_history），因此「测试台导航」页看到的自检状态与本页报告始终一致；初始化 / 终止的最近 20 次记录保留在 ops_history。

6. 接口

方法路径说明
GET/api/testbench/pending待注册（草稿）测试台清单 + 已注册台数
POST/api/testbenches/export导出待注册测试台（bench_ids / include_registered），落盘 + 回传内容
POST/api/testbenches/{id}/init装备初始化（{mode, timeout, note}）→ 结果 + 报告条目
POST/api/testbenches/{id}/teardown装备终止 → 结果 + 报告条目
POST/api/testbenches/{id}/selfcheck硬件自检 → 结果写回注册库 + 报告条目
GET/api/testbench/reports报告清单（kind / bench_id / limit）
GET/api/testbench/reports/dir目录信息：路径 / 文件数 / 占用空间
GET/api/testbench/reports/{file}报告内容（HTML）
POST/api/testbench/reports/open打开报告目录，或 {filename} 定位到具体报告

统一返回体：{success, message, result, report, testbench}；失败时 success=false 并带中文原因，界面以轻提示呈现，不白屏。
