# 测试用例接入实时数据监视

本文面向**编写测试用例的工程师**，说明如何在 pytest 用例中把过程数据推送到 Runner 的「实时监视」窗口。
只涉及用例侧要写的那几行代码；平台侧（Redis 实例、接口、界面）由 Runner 安装包与现场部署负责。

---

## 一、适用范围与前提

| 项目 | 说明 |
| --- | --- |
| 适用对象 | 经 Runner 执行链路调起的 pytest 用例（含 TPS 清单编排的单步与整例） |
| 用例侧依赖 | 仅 `import ate_rt`，无需安装包、无需配置项 |
| 平台侧前提 | Runner 所在机器能连到 Redis；连接串由 `ATE_RT_URL` 指定（默认 `redis://127.0.0.1:6379/0`） |
| 任务号来源 | Runner 启动用例时注入环境变量 `ATE_RT_TASK_ID`，用例**不需要**自己生成 |

三条不变式，先记住，后面所有规范都由此推导：

1. **不影响判定**：监视通道任何异常都不上抛，用例该 PASS 还是 PASS。
2. **不影响时长**：写入是旁路动作，不能引入等待、不能拖慢采样节拍。
3. **不进入基线**：写进去的是过程观感数据，判定仍以阈值与返回值结果文件为准。

---

## 二、三条最小规则

| 规则 | 做法 | 原因 |
| --- | --- | --- |
| 只 import，不初始化 | 直接 `import ate_rt`，用模块级函数写数 | 模块级默认会话自动读取任务号，连接懒建，零配置 |
| 键用英文稳定标识，中文名放 `label` | `declare("vdd", label="供电电压")` | 键名是数据项唯一标识，改名等于换数据项；显示名可以随时改 |
| 只写过程量，不写结论 | 中间测量值、阶段号、状态文本 | 结论与阈值判定走 `ctx.log()` 与用例返回值，避免两套口径 |

---

## 三、最小可用示例

Runner 执行链路下，下面 12 行就是完整接入：

```python
import ate_rt


def test_output_voltage(ctx):
    v = ctx.command("psu", "measure_voltage")      # 直接返回测量值（非 dict）

    ate_rt.declare("vout", label="输出电压", unit="V", group="供电", lo=3.0, hi=3.6)
    ate_rt.write("vout", v)
    ate_rt.event("输出电压测量完成")
```

三件事已经自动完成：任务登记（任务号取自 `ATE_RT_TASK_ID`）、数据项声明、数据点写入。
执行页点「实时监视」即可看到 `供电 / 输出电压` 一项，数值为本次测量值。

> 短用例（单次测量、执行时间不足 1 s）意义有限——监视窗口按 1 Hz 取样，一次写入只能看到一个点。
> 这类用例建议只写 `event`，把逐点监视留给有过程的长用例。

## 四、两种用法，按用例形态选

| 用法 | 写法 | 适用 | 注意 |
| --- | --- | --- | --- |
| 模块级默认会话 | `ate_rt.declare/write/write_many/event` | 一次性测量、少量数据点 | 全程共用一个连接，进程结束自动关闭 |
| `Monitor` 会话 | `with ate_rt.Monitor(name=..., tps=...) as mon:` | 长时序、分阶段、需要标注任务名的用例 | 退出时自动把任务状态置 `done`（异常退出置 `error`） |

长用例推荐第二种，因为可以把用例名与 TPS 一起登记，监视窗口标题栏能直接看出这是哪个用例：

```python
import time
import ate_rt


def continuous_run_soak(ctx):
    total_s = 90

    with ate_rt.Monitor(name="连续运行稳定性", tps="spm_rh_dyn") as mon:
        mon.declare("vdd", label="供电电压", unit="V", group="供电", lo=3.0, hi=3.6)
        mon.declare("rpm", label="实际转速", unit="rpm", group="运动", lo=0, hi=3800)
        mon.declare("stage_no", label="测试阶段", group="流程", lo=1, hi=3)
        mon.event(f"连续运行开始（{total_s} s）")

        for i in range(total_s):
            vdd = ctx.driver("dmm").do("measure_dc_voltage")["value"]
            rpm = ctx.driver("spin").do("read_speed")["value"]
            stage = 1 if i < 30 else 2

            mon.write_many({"vdd": vdd, "rpm": rpm, "stage_no": stage})
            time.sleep(1)

        mon.event("连续运行结束")
```

**不要自己编任务号。** 只有在 Runner 之外单独跑脚本（例如离线调试）时，才需要显式传
`ate_rt.Monitor(task="my-debug-001")`，否则监视窗口里找不到这条任务。

## 五、数据项声明字段

`declare(name, **meta)` 支持以下字段，其余忽略：

| 字段 | 作用 | 建议 |
| --- | --- | --- |
| `label` | 界面显示名 | 中文、含单位语义，如「供电电压」；不填则等于键名 |
| `unit` | 数值单位 | `V` / `A` / `mA` / `Hz` / `rpm` / `℃`；同组内保持一致 |
| `group` | 分组 | 供电 / 运动 / 信号 / 负载 / 流程，界面按组排布 |
| `kind` | 数据类型 | `float`（默认）或 `text`；**填了 `lo`/`hi` 会自动按数值处理** |
| `lo` / `hi` | 期望区间 | 强烈建议数值项都填：界面据此对越限值着色，异常一眼可见 |

命名约束：

- 键名用**字母、数字、下划线**，长度控制在 24 字符内，全局唯一且**一次定好不要改**。
- `_event` 为库保留键（`event()` 专用），不要占用。
- 同一任务内不要用同一个键表示两种物理量；单位变了就应换键（例如 `vdd_mv` 与 `vdd`）。

## 六、写入节奏与数据量

| 项 | 设计值 | 说明 |
| --- | --- | --- |
| 界面刷新 | 1 Hz，可选 2 Hz | 由监视页发起轮询，与用例写入频率无关 |
| 每通道保留点数 | 3600（约 1 h @1 Hz） | `Monitor(keep=...)` 或 `write(..., keep=...)` 可覆盖 |
| 曲线条数 | 最多 4 条 | 界面限制，用来对比关键量即可 |
| 任务与曲线过期 | 24 h | Redis TTL，过期后不占空间，无需用例清理 |

四条纪律：

1. **每个采样周期每项只写一次。** 写入是一次 Redis 往返；在 1 ms 级循环里逐点写会明显拖慢用例。
2. **采样快于 1 s 时先降采样。** 做法是保留最近值或做 n 点平均，再每秒写一次。
3. **过程数据不落结果文件。** 曲线只服务于"当下正在发生什么"，统计量仍由用例返回给判定。
4. **非有限值必须先过滤。** 库会把 `float('nan')`、`inf` 原样写入，前端画不出来：

```python
import math


def _clean(value):
    """过滤 None 与非有限值，避免污染曲线"""
    try:
        num = float(value)
    except (TypeError, ValueError):
        return None
    return num if math.isfinite(num) else None


payload = {"vdd": _clean(vdd), "rpm": _clean(rpm)}
mon.write_many({k: v for k, v in payload.items() if v is not None})
```

`write_many(dict)` 是便捷封装，内部逐项调用 `write`，不要把它当成批量提交事务。

## 七、时间戳与事件打点

| 需求 | 写法 |
| --- | --- |
| 默认（推荐） | `mon.write("vdd", v)` —— 库用当前时间生成 `ts_ms` |
| 与外部时钟对齐 | `mon.write("vdd", v, ts_ms=int(t * 1000))`，用于数据源自带时标（如仪器缓存回放） |
| 补历史点 | 连续调用并逐个传 `ts_ms`，曲线按时间升序展示 |
| 阶段标记 | `mon.event("进入稳态运行")` —— 写入 `_event` 文本项，界面显示为事件流 |

`event()` 每任务保留 200 条，且自带 `HH:MM:SS` 前缀。**不要用它替代日志**：逐行日志走 `ctx.log()`，
事件只放阶段切换、负载投入、保护触发这类"值得在曲线上标一根线"的时刻。

## 八、失败与降级语义

| 场景 | 用例侧表现 | 需要做什么 |
| --- | --- | --- |
| Redis 正常 | 数据实时可见 | — |
| Redis 未启动 / 地址错 | `Monitor` 退化为空操作，stderr 打印一次提示 | 无需改用例；修部署即可 |
| Redis 中途断开 | 当前写入失败并记入 `last_error`，用例继续 | 无需改用例 |
| 需要临时关闭监视 | 设 `ATE_RT_DISABLE=1` | 用于验证"关掉监视不影响测试" |
| 用例断言失败 | `with Monitor` 退出时任务状态置 `error` | 无需处理 |

主动自检（放在用例开头或离线脚本里）：

```python
info = ate_rt.store_info()
print(info)
# Redis 可用：{'backend': 'redis', 'ok': True, 'url': 'redis://127.0.0.1:6379/0',
#             'db': 0, 'prefix': 'ate:rt', 'keep': 3600, 'ttl_s': 86400}
# Redis 不可用：{'backend': 'none', 'ok': False, 'error': 'Redis 不可用（…）：timed out'}
```

用例内部只想静默判断可用性时，读会话属性即可，不要 `try/except` 包住业务代码：

```python
mon = ate_rt.session()
if mon.store_backend == "none":
    ctx.log(f"实时数据不可用：{mon.last_error}")
```

## 九、排障对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 监视页任务列表为空 | 用例自建了 `Monitor` 且没传 `task`，任务号与 Runner 不一致 | 删掉自建任务号，走默认会话 |
| 有任务、无数据项 | 只写了 `None`，被过滤后没有任何数据点 | 先过滤再写；确认驱动返回了数值 |
| 曲线只有一个点 | 短用例 / 只写一次 | 属于预期，短用例建议改用 `event` |
| 曲线中间断档 | 采样间隔不均或超过保留点数被裁掉 | 固定采样节拍；长用例可调大 `keep` |
| 数值明显不对 | 单位换算错，或 `nan` 被写入 | 统一单位；按第六节示例过滤非有限值 |
| 页面提示「存储未连接」 | Redis 未启动、地址错、网络不通 | 查 `ATE_RT_URL` 与 Redis 进程；`/api/monitor/info` 会给出错误原因 |
| 执行时间被拖长 | 每采样点多次写入 | 改为每周期写一次，或先降采样 |

## 十、验收清单

接入完成后按四步确认：

1. `python -c "import ate_rt; print(ate_rt.store_info())"` 返回 `ok: True`；
2. 用 Runner 跑该用例，执行页点「实时监视」，任务出现在列表中且状态为 `running`；
3. 数据项按分组显示，数值随执行推进而刷新，越限值有颜色区分；
4. 用例结束后任务状态变为 `done`（失败时为 `error`），窗口按配置自动收起。

## 十一、版本差异与注意事项

| 版本 | 变化 | 对用例的影响 |
| --- | --- | --- |
| 2.0.0（当前） | 移除 SQLite 兜底，仅支持 Redis | 用例代码零改动；但没有 Redis 时不再有本地库可视 |
| ≤ 1.x | Redis 优先，连不上回落本地 SQLite | 升级后旧机器的 `backend/.ate_rt/realtime.db` 不再被读取 |

两点现场提醒：

- **升级前**若依赖过本地库视图，请先归档 `backend/.ate_rt/realtime.db`，升级后它以 Redis 为准。
- 监视窗口是**旁路观察者**：关掉窗口、切到 2 Hz、暂停刷新都不影响用例执行与判定。

## 附：键空间（仅供排障核对）

| 键 | 类型 | 内容 |
| --- | --- | --- |
| `ate:rt:tasks` | ZSET | 任务索引：`task_id` → 开始时间 |
| `ate:rt:task:<task_id>` | HASH | 任务元数据：`name` / `tps_id` / `uut` / `mode` / `status` / `started_at` / `ended_at` |
| `ate:rt:task:<task_id>:channels` | ZSET | 数据项声明顺序 |
| `ate:rt:task:<task_id>:ch:<name>` | HASH | 数据项元数据 + 最新值 |
| `ate:rt:task:<task_id>:ch:<name>:z` | ZSET | 曲线点：时间戳 → 数值，按 `keep` 裁剪 |

核对命令示例：

```text
ZREVRANGE ate:rt:tasks 0 4 WITHSCORES
HGETALL  ate:rt:task:<task_id>
HGETALL  ate:rt:task:<task_id>:ch:vdd
ZRANGE   ate:rt:task:<task_id>:ch:vdd:z -3 -1 WITHSCORES
```
