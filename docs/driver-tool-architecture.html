后端 driver / tool 模块拆分设计方案

把「装备助手工具」与「可编程设备驱动」拆成两个独立模块：tools/ 面向装备助手的工具，drivers/ 面向可编程设备的驱动；驱动层用工厂方法按后端注册信息选择具体实现，首期落地示波器一族。

1. 现状问题：三件事揉在一处

现在 backend/instrument_tools.py（774 行）里，ScopeSession 一个类同时承担了传输收发、泰克 SCPI 方言、波形与测量解析、以及工具卡片与路由。_is_scope() 还是靠名称关键字猜设备类型。

现状问题
ScopeSession 同时管 socket、SCPI 命令字、波形解析、卡片加一台非泰克示波器要改同一个类，容易碰坏已验证逻辑
真实 / 模拟两套分支（_waveform_real 与 _waveform_sim、_measure_real 与 _measure_sim）两条代码路径各自演化，模拟与实测行为会漂移
_is_scope() 用关键字猜类型判定不权威，注册信息一变就误判
路由、会话字典、业务编排同处一个文件单元测试必须拉起 FastAPI，无法只测驱动

2. 分层与依赖方向

硬约束是依赖单向，下层不认识上层：驱动层不读注册库、不读 FastAPI，只接收一个设备描述字典，因此可以脱离 Web 单独单测。

tools/ — 装备助手工具层
卡片清单 · 会话管理 · 动作编排 · FastAPI 路由。只依赖抽象接口，不认识任何厂商 SCPI 命令。
▼ 只调用抽象方法
drivers/ — 可编程设备驱动层
DeviceDriver / ScopeDriver 抽象 + 具体实现 + 工厂。只吃设备描述字典，不感知持久化与 Web。
▼ 只发命令 / 收应答
drivers/transport/ — 传输层
Socket / Serial / VISA(预留) / Simulate。唯一与真实仪器打交道的地方，模拟模式只替换这一层。

4. 传输层：模拟与真实共用一套驱动

这是整个方案里最关键的一条决定 —— 模拟不另写一套驱动，只在传输层换实现。命令序列、状态机、解析逻辑只有一份，模拟因此能真实地验证驱动逻辑。

传输触发条件（来自注册信息）实现要点
SocketTransportinterface=LAN，协议含 raw socket / SCPI（泰克 4000、多数 5025）create_connection、行结束符 \n、读超时可覆盖；写命令与查询分离
SerialTransportinterface=SERIALserial_port + baudrate；缺 pyserial 抛 DependencyMissing
VisaTransport 预留协议含 VXI-11，或资源地址形如 TCPIP0::…::INSTR走 pyvisa；缺失则降级为 Socket 并在日志与界面标注实际通道
SimulateTransportmode=simulate，或真实连接失败且允许降级命令→应答规则表；未知命令回 0/空不报错；波形样本在传输层生成

5. 驱动层：抽象契约与工厂

DeviceDriver（通用）

  • connect() / close() / identify()
  • capabilities() → 能力集合
  • command_log() → 命令日志
  • 类属性 kind（scope/dmm/psu/eload）、family

ScopeDriver（示波器契约）

  • run / stop / single / autoset
  • get_timebase / set_timebase
  • get_channels / set_channel(display·scale·offset·coupling)
  • acquire_waveform(ch, points) → Waveform
  • measure(ch, types) → Measurement[]

职责划分

  • 通用计算放 base_scope.py：measure() 先试仪器原生测量（MEASUrement:ADDMEAS + MEAS<x>:VALUE?），单项失败回退为「用波形自算」Vpp / RMS / 频率 / 周期 / 均值 / 上升时间，并标注来源 instrument 或 derived。
  • 厂商类只写方言：命令字、波形前导解析（WFMOutpre:* 标定）、通道上限（4/8 通道）。
  • 零依赖：数据类用标准库 dataclass，不引入 numpy；pyserial / pyvisa 均为可选。
  • 能力协商：动作超出 capabilities() 时，工具层直接给「该型号不支持」的中文原因，而不是把仪器难懂的 SCPI 错误抛给用户。

工厂选择算法（先具体后兜底）

① 显式覆盖注册信息里的 driver 字段，现场特殊机型手工指定，优先级最高
② 型号匹配vendor + model 拼接后正则匹配，兼容 "Tektronix MSO54" 这类合并写法
③ 类别兜底category / protocol 关键字命中通用 SCPI 驱动
④ 明确拒绝都不中 → DriverNotFound，附"当前支持的型号清单"

驱动层不持久化配置：注册库 testbenches.json 是唯一事实源，工厂只吃一个字典；因此装备属性配置页改完 IP，下次建会话自然就是新值。

6. 工具层

文件职责
base.pyToolBase：id / name / subtitle / desc / protocol / capabilities / available / driver_kind
cards.py卡片清单数据（数字示波器可用，万用表 / 电源 / 电子负载规划中）；新增工具 = 加一条记录

oscilloscope_tool.py11 个动作 → 驱动方法；参数校验、单位换算、中文错误；响应结构保持 {success, message, result, log, state}
routes.pyregister_routes(app, tps_dir)，路径与现有 7 个接口完全一致

接口契约：前端零改动

接口变化
GET /api/tools不变；卡片新增可选字段 driver_kind
GET /api/tools/oscilloscope/bindings不变；is_scope 改由驱动层判定（更准）
POST /api/tools/oscilloscope/connect新增 driver（驱动类名）与 transport（实际通道类型）
POST /api/tools/oscilloscope/action不变；失败时新增 code 便于前端分支
GET /api/tools/oscilloscope/state不变；新增 driver / transport

新增字段全部是追加，老前端忽略即可；业务失败仍维持 HTTP 200 + success:false，前端不用改判断逻辑。

7. 并发、超时与错误模型

并发

FastAPI 同步路由跑在线程池：驱动实例自身不加锁，由会话管理器对同一设备串行化命令；不同设备天然并行。

超时

统一在传输层：普通查询 2s（可被请求覆盖）、波形查询 5s、连接 2s。会话空闲 10 分钟自动断开，不长期占仪器 socket。

错误映射

异常工具层返回
DriverNotFound"未找到 XX 的驱动，当前支持：…"
DependencyMissing"缺少 pyserial，请 pip install pyserial"
NotConnected"尚未连接设备，请先运行工具并连接"
Timeout"仪器无响应（超时 Xs），请检查 IP/端口"
Unsupported"该型号不支持自动设置"
ProtocolError带回应答片段，便于排查

8. 迁移步骤：五步，每步可独立验证

1
抽传输层把 socket 与模拟收发从 ScopeSession 搬进 transport/，只搬运不改行为 → 现有 test_tools.py 应全绿。
2
抽驱动契约 + 泰克驱动迁移 SCPI 方言与波形解析；两条 *_real / *_sim 分支合并为「驱动 + SimulateTransport」→ 模拟频率 1.000 MHz 等既有断言保持通过。
3
建工厂与匹配表DRIVER_SPECS 表驱动单测：合并 model 串、未知型号、显式覆盖三种情形。
4
建工具层迁移卡片、会话、路由；instrument_tools.py 转 shim，main.py 改挂 tools.routes → 12 个既有接口回归 + 装备助手端到端。
5
收尾与文档预设 JSON 增加可选 driver 字段说明；drivers/README.md 写"接入新设备 5 步"；同步架构文档。

测试计划

  • 单测（新增 backend/tests/，pytest）：工厂匹配表、波形前导解析（固定样本）、SimulateTransport 命令回放、capabilities() 拒绝路径、同设备命令串行化。
  • 端到端：沿用现有 test_tools.py（注册测试台 → 绑定 → 模拟全流程 → 真实模式降级）。
  • 回归：既有 12 个接口（测试执行 / 记录 / 装备属性配置 / 测试台注册）。
  • 硬指标：拆分前后同一套端到端脚本的断言逐条不变地通过（模拟模式下的测量值、波形点数、日志条数一致）。

9. 风险与对策

风险对策
预设里 protocol 写 VXI-11，实现却走 raw socket传输层显式映射，并把实际通道类型回传前端与日志，不靠字符串自欺
model 是合并串（"Tektronix MSO54"）匹配时用 vendor + model 拼接后统一小写再正则，不依赖字段拆分
pyserial / pyvisa 未必安装构造传输时抛 DependencyMissing，工具层转"待补依赖"提示，不阻断自检
拆分期间老代码仍被 import保留 instrument_tools.py shim 一个版本周期，main.py 一次性改挂
模拟与真实再次漂移硬约束：模拟只许改传输层；驱动层出现 if simulated: 分支视为设计违规，评审拦截
工控机零依赖约束驱动与工具层只用标准库（socket / threading / dataclasses），pyserial、pyvisa 均为可选

10. 后续扩展

接入新仪器 = 一条规则 + 一个类

能力表驱动，新增设备只需在 DRIVER_SPECS 加一条匹配规则并实现驱动类；这与"把仪器说明书喂给 AI 自动生成适配层"的探索方向天然契合。

与测试执行侧打通

驱动注册信息可直接生成 equipment_demo.xml，让装备清单、注册库、驱动三者同源。

从工具到动作编排

示波器工具稳定后，tools/ 复用到万用表 / 电源 / 电子负载，并演进为多设备协同的测试动作编排。
