# 03 · ASML：设备侧量测与测试闭环

> 前置说明：ASML 不生产 ATE。本章拆的是「设备如何自证精度、如何用测量结果反哺参数」，这才是与我们相关的那一半。
> 来源见 `README.md` 引用清单 R9–R15。

## 一、产品在晶圆厂里的位置

```
设计 ──► 掩模 ──► 光刻(ASML 扫描机) ──► 刻蚀/沉积 ──► 量测(ASML YieldStar / KLA)
                        ▲                                    │
                        │                                    │ overlay / CD / 缺陷
                        └────── 计算光刻(Brion) + 补偿参数 ◄──┘
                                       ▲
                                  电子束检测(HMI eScan)
```

一句话：**ASML 卖的不是「测一次」，而是「让下一次印得更准」。** 测试在这里是闭环的一环，不是终点判定。

## 二、TWINSCAN：把「量」与「曝」拆成两条流水线

TWINSCAN 的核心结构特征是**两个完整的工件台**（wafer stage）：一片在曝光位接受曝光，另一片同时在量测位做对准与调平，然后两片交换位置。

| 传统单台结构 | 双工件台结构 |
| --- | --- |
| 量测与曝光串行，量测期间激光器闲置 | 量测与曝光并行，激光器利用率大幅提升 |
| 单纯提升机械速度会遇到物理极限 | 用并行把「非曝光时间」藏起来 |

**这条思路对我们的启发不在机械，而在编排**：一个测试台位在等设备稳定/等温漂时，另一台位可以已经在跑；我们现在的执行模型是「一个任务占死一台」，时间利用率低正是缺这类并行编排。

## 三、设备内建量测：精度怎么自证

扫描机内部有两套常驻测量：

- **对准（alignment）**：曝光前测晶圆上的对准标记，解算出晶圆的位置与形变；
- **调平（leveling）**：测焦面高度分布，保证曝光时始终在焦深内。

ASML 官方对量测软件的描述是：扫描机量测软件使用**机床过程的计算模型**，去预测并协调各机电模块的动作（R10）。这句话的技术含量在于——它不是「测了就调」，而是「先建模预测，再用测量校正」。

配套的两类外部量测构成闭环：

| 设备 | 原理 | 输出 | 用途 |
| --- | --- | --- | --- |
| YieldStar 500 | 衍射式光学量测，集成在生产路径旁 | overlay、focus | 产片上快速监测，纳米级精度 |
| YieldStar 1385 | 独立式光学量测 | 后蚀刻 overlay | 离线复核与批次监控 |
| HMI eScan 1000 | 电子束，9 束 3×3 阵列，单源架构 | 单芯片级缺陷与电压衬度 | 找图形缺陷，定位到具体 die |

## 四、holistic lithography：把三家能力接成一个环

ASML 官方对自家产品结构的表述是：把**计算建模、光学量测、电子束检测与光刻系统集成**在一起（R9）。业界把这一整套叫 holistic lithography，其闭环可以画成四段：

1. **算**：计算光刻（2007 年收购的 Brion）根据设计与工艺模型算出掩模图形与工艺窗口；
2. **曝**：扫描机按参数曝光，同时用内建对准/调平保证落在焦深与套刻窗口内；
3. **测**：YieldStar 测 overlay/focus，HMI 测缺陷；
4. **修**：把测量偏差分解成可归因的项（机台、掩模、工艺），生成下一批的补偿参数，回到第 1 步。

**关键工程细节：偏差必须可归因。** 只测不分解，就只是记录；分解到「哪台机、哪层掩模、哪个工艺段」，才能生成有用的修正量。这与我们做测试数据时「只知道失败、不知道为什么失败」是同一类问题。

## 五、映射到 ATE Runner 的四条

| ASML 做法 | 我们的对应物 | 建议 |
| --- | --- | --- |
| 曝光前对准、调平（先测量再动作） | 用例执行前的设备自检、预热、量程确认 | 把「预检」做成不可跳过的固定阶段，失败即终止而非硬跑 |
| 用计算模型预测再校正 | 仿真模式、Mock 驱动 | 已有雏形；可加「基准件（golden unit）定期回归」 |
| 测量结果分解成归因项 | 结果标准化 + MES 回传 | 目前偏 pass/fail，建议补「偏差归因字段」（设备/夹具/环境/程序） |
| 量测与曝光并行 | 单任务独占台位 | 缺并行编排；短期可先做「台位排队 + 预估时长」，长期再谈时间片 |

## 六、不该照搬的部分

1. **不要自研量测硬件**：ASML 的护城河是光学与电子光学，不是软件；我们的护城河应是接入与编排。
2. **不要追求 nm 级指标**：装备与板卡测试关心的是功能正确性与参数裕度，不是套刻精度。
3. **不要做整机标定体系**：那需要计量溯源能力，超出 ATE 软件平台的范围。

## 七、一句话总结

> ASML 教我们的是「测试不是终点，是下一轮参数的输入」；NI 教我们的是「执行器、驱动、配置三层解耦，靠 site 与 pin map 吸收硬件差异」。前者改我们的数据模型，后者改我们的软件分层。
