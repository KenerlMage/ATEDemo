# 01 · 定位纠偏与三条技术路线

## 一、为什么必须先纠偏

把 ASML 与 NI 并列成「两家 ATE 厂商」会在评审现场被一句话问倒：**ASML 不卖 ATE。**

ASML 的产品线只有四类，全部围绕「把图形准确印到晶圆上」：

| 类别 | 代表产品 | 在晶圆厂里干什么 |
| --- | --- | --- |
| 光刻系统 | TWINSCAN NXT（DUV）、EXE（High-NA EUV） | 曝光，图形转移的执行者 |
| 光学量测 | YieldStar 500 / 1385 | 测 overlay、focus，判断印得准不准 |
| 电子束检测 | HMI eScan 1000 / 1100 | 找单个芯片级缺陷，9 束 3×3 阵列 |
| 计算光刻与软件 | Brion 系列 | 算掩模图形、算工艺窗口，反哺扫描机参数 |

晶圆厂里「测试」这件事由两类设备分担：**ATE**（Advantest、Teradyne，做电性功能与参数测试）与**量测/检测**（ASML、KLA，做几何与缺陷）。ASML 属于后者，而且是「设备自带量测」的极致样本。

> 因此本章的正确写法是：NI = 平台化 ATE 的代表；ASML = 设备侧量测闭环的代表。二者解决的是不同问题，可借鉴的也正是这两件不同的事。

## 二、业界实现归为三条路线

### 路线 A：专用 per-pin ATE

一个机柜里塞满数字通道板，每根引脚配独立的时序发生器、驱动器、比较器、参数测量单元（PPMU），板卡之间靠专用同步总线对齐时钟；被测芯片通过 DUT 板（load board）接到测试头，测试头再对接探针台或分选机。

软件形态是**测试程序 + 编译器**：工程师用厂商专有语言（如 Advantest 的 IG-XL）描述向量、时序、电平、测试流程，编译器把程序编译成通道板可执行的微码。

| 特征 | 说明 |
| --- | --- |
| 优势 | 引脚密度、时序精度、量产节拍的天花板最高 |
| 代价 | 封闭生态、单机价格高、改型慢、程序不可移植 |
| 典型 | Advantest V93000（test processor per pin）、Teradyne UltraFLEX |

### 路线 B：模块化平台（NI 的路线）

用标准 PXI/PXIe 机箱 + 模块化仪器替代专用机柜；主机是普通工业 PC，操作系统是 Windows；测量能力由插什么模块决定，扩展靠加模块而不是换整机。

软件分三层：**执行器**（TestStand，管流程、步骤、报告、并行）、**驱动**（每个模块的 API，多为 IVI 或厂商专用）、**配置**（引脚映射、site 划分、限值与统计）。

| 特征 | 说明 |
| --- | --- |
| 优势 | 开放、可按需裁剪、软件可复用、研发与产线同一套代码 |
| 代价 | 单通道性能不及专用机，机箱槽位与散热是硬约束，实时性依赖机箱背板 |
| 典型 | NI STS T1/T2/T4（半导体版）、NI ATE Core Configurations |

### 路线 C：设备内建量测与自校准（ASML 的路线）

设备自己带传感器：曝光前测对准标记、测焦面，曝光后用量测机台复核，结果反过来修正下一批的补偿参数。设备不依赖外部 ATE 判定自己「干得对不对」，而是内建一套**精度自证机制**。

| 特征 | 说明 |
| --- | --- |
| 优势 | 精度可追溯、参数可持续收敛、异常能被自身量测发现 |
| 代价 | 传感器与模型是核心竞争力，投入大，且只在「有物理量可测」的场景成立 |
| 典型 | TWINSCAN 的对准/调焦、YieldStar、HMI e-beam |

## 三、三条路线一张表

| 维度 | A 专用 per-pin ATE | B 模块化平台（NI） | C 设备内建量测（ASML） |
| --- | --- | --- | --- |
| 解决的核心问题 | 大规模量产电性测试 | 中等规模、多品种、快速改型的测试 | 制造精度是否达标、如何收敛 |
| 硬件形态 | 专用机柜 + 通道板 + 测试头 | PXI/PXIe 机箱 + 模块 | 设备本体 + 内建传感器 |
| 软件形态 | 专有测试语言 + 编译器 | 通用执行器 + 驱动 + 配置 | 设备控制软件 + 模型 + 数据闭环 |
| 扩展方式 | 加通道板（受机柜限制） | 加模块、加机箱 | 加传感器、改模型 |
| 升级风险 | 高（编译器与硬件强耦合） | 中（驱动版本兼容矩阵） | 高（涉及整机标定） |
| 单点性能 | 最高 | 中高 | 不适用（比的是精度，不是速率） |
| 生态开放度 | 低 | 高 | 低（但对客户开放数据接口） |
| 典型企业 | Advantest、Teradyne | NI（Emerson） | ASML |

## 四、选型判据（判断落在哪条路线）

1. **被测对象的确定性**：引脚定义、时序规约固定的量产芯片 → A；板级/系统级、接口常变 → B。
2. **批量与节拍**：百万片级、单片测试时间以秒计 → A；千片级、研发与小批量 → B。
3. **精度与同步要求**：需要 ps 级通道间偏斜、GHz 级向量速率 → A；ns 级、百 MHz 级 → B 够用。
4. **现场可维护性**：产线不能停机、备件要通用 → B 更友好；A 的备件与校准依赖原厂。

## 五、我们（ATE Runner）站在哪

**判断：我们既不是 A 也不是 C，而是 B 的轻量版，并借了 C 的一点思路。**

- 后端 + Runner + 驱动适配层 + TPS（pytest）的结构，本质是「执行器 + 驱动 + 配置」三层解耦，与 NI 同构，只是把 TestStand 换成了 pytest、把 PXI 换成了「现有测试台里已有的仪器」。
- 我们的「仿真模式 / Mock 驱动」对应的是 C 里的自校准思想雏形——用确定性的假数据验证链路，而不是靠现场试错。
- 我们**不具备** A 的硬指标（per-pin 时序、向量速率），也不该往那走：那是一条需要自研通道板与编译器的重资产路线。

由此得出汇报里最有价值的一句话：

> 我们做的是「开放平台 + 轻量执行器」，竞争点不在单通道性能，而在**接入成本、可编排性、可追溯性**。对标 NI 学架构，对标 ASML 学闭环，不必对标 Advantest 学性能。
