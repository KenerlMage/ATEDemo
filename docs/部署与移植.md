# 部署与移植说明（换 PC 必读）

本文件保证 MockRunner / MockController 搬到另一台 Windows PC 后可以直接运行。
目标机只需要：**Windows 10/11 x64 + Microsoft Edge + Python 3.10~3.13（64 位）**。
Node.js 只有在前端源码改动、需要重新构建时才需要。

## 1. 仓库里已经带了什么

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 前端构建产物（Runner） | `frontend/dist/` | 已提交，目标机无 Node 也能直接跑 |
| 前端构建产物（Controller） | `controller-web/web_dist/` | 已提交，由后端 `/ui/` 托管 |
| Python 依赖清单 | `backend/requirements.txt`、`requirements.txt` | 版本已固定 |
| Edge 启动脚本 | `tools/open_ui.ps1`（两个工程都有） | 按注册表/常见路径/PATH 依次找 Edge |
| 离线依赖目录（可选） | `wheels/` | 有就优先离线安装 |

## 2. 首次运行

### MockRunner

```bat
:: 双击或在 cmd 中执行
start_all.bat
```

脚本会依次：找 Python（`.venv` → PATH）→ 缺依赖则安装 → 检查 `frontend/dist`（存在就跳过 Node）→ 检查 8000 端口 → 启动后端 → 用 Edge 打开 `http://127.0.0.1:8000/`。

跳过自动开浏览器：`set ATE_NO_BROWSER=1`。

### MockController

```bat
start_controller.bat
```

脚本会依次：找 Python（`ATE_PYTHON` → 本工程 `.venv` → 同级 `MockRunner\backend\.venv` → PATH；都没有则尝试 `python -m venv .venv`）→ 缺依赖则安装（有 `wheels\` 时离线装）→ 检查 8070 端口 → 启动后端 → 用 Edge 打开 `http://127.0.0.1:8070/ui/`。

两个工程可以放在任意目录，**不要求** `D:\ATE`，也不要求两个工程同级；只有 Controller 的"同级 MockRunner venv 兜底"和 `seed_assistants.py` 的默认货架路径假设同级，可用环境变量覆盖。

## 3. 环境变量

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `ATE_PYTHON` | 指定 Python 解释器（两个工程都认） | 自动探测 |
| `MOCK_CONTROLLER_PYTHON` | e2e 测试用解释器 | 自动探测 |
| `ATE_NO_BROWSER` | `1` 时不自动开浏览器 | 未设置 |
| `ATE_CONTROLLER_URL` / `MOCK_CONTROLLER_URL` | Runner 访问 Controller 的地址 | `http://127.0.0.1:8070` |
| `MOCK_CONTROLLER_REPO` | Controller 数据根目录 | 工程内 `repo/` |
| `ATE_ASSISTANT_SHELF` | `seed_assistants.py` 的 Runner 货架路径 | 同级 `MockRunner\backend\assistant_shelf` |
| `ATE_TPS_CACHE_DIR` / `ATE_TPS_SOURCE` | Runner TPS 缓存与来源 | 工程内 |
| `ATE_CONSTANT_SOURCE_WHITELIST` / `ATE_CONSTANT_SIGNING_KEY` | 机器常数来源白名单与签名 | 见代码默认 |

## 4. 端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| Controller | 8070 | 测试用 8071+ |
| Runner 后端 | 8000 | 测试用 8020/8025 |
| 前端 dev（仅开发） | 5173 / 5174 | 生产由后端托管静态文件 |

端口被占用时脚本会直接报错并给出 `netstat` 命令，不会静默失败。

## 5. 离线部署（目标机无外网）

1. 在联网机下载 wheel：

```powershell
pip download -r requirements.txt -d wheels --only-binary=:all:
```

2. 把 `wheels\` 连同工程一起拷到目标机。
3. 正常执行 `start_all.bat` / `start_controller.bat`，脚本检测到 `wheels\` 会走 `--no-index --find-links wheels`。

注意：`pip download` 默认按当前机器的 Python 版本与平台下载。目标机 Python 小版本不同时，需加 `--python-version 3.13 --platform win_amd64 --implementation cp --abi cp313` 重新下载。

## 6. 搬迁检查清单

- [ ] 拷贝整个工程目录（含 `frontend/dist`、`controller-web/web_dist`、`wheels/`）
- [ ] 目标机 Python 3.10+ 64 位在 PATH，或设置 `ATE_PYTHON`
- [ ] 目标机有 Edge（`start_all.bat` 会自动调用）
- [ ] 8070 / 8000 未被占用
- [ ] Controller 数据目录可写（默认工程内 `repo/`，或用 `MOCK_CONTROLLER_REPO` 指到可写盘）
- [ ] Runner 工作目录可写（`workspace/`、`envs/`、日志目录）
- [ ] 若两个工程不同级：设置 `ATE_ASSISTANT_SHELF`、`MOCK_CONTROLLER_URL`

## 7. 不要拷的东西

| 不拷 | 原因 |
| --- | --- |
| `.venv/` | 记录创建时的绝对路径，换盘符/用户名可能失效；到目标机重建更快更稳 |
| `__pycache__/`、`.pytest_cache/`、`.pytest_tmp*/` | 无意义，且可能因占用导致删除失败 |
| `node_modules/` | 平台相关、体积大；只有需要重新构建时才装 |
| `repo/`（Controller 数据） | 除非要带历史数据，否则让目标机自己初始化；带数据时注意数据库版本 |
| `workspace/`（Runner 运行产物） | 按需迁移，不要带临时 TPS 缓存 |

## 8. 换机后自检

```powershell
# Controller
curl http://127.0.0.1:8070/api/v1/health
# Runner
curl http://127.0.0.1:8000/api/health
```

浏览器打开对应地址，确认：

1. 页面能加载（说明 `dist` / `web_dist` 有效）；
2. 装备树/机器常数能读到数据（说明 Controller 数据目录可写、Runner 能连上 Controller）；
3. 执行页能列出 TPS（说明 `ATE_TPS_CACHE_DIR` 可写）。

## 9. 常见问题

**Python 不在 PATH**
装 Python 时勾选 "Add python.exe to PATH"；或 `set ATE_PYTHON=C:\Python313\python.exe` 后重跑脚本。

**双击脚本闪退**
在 cmd 里执行同名 bat，能看到具体错误行；脚本所有失败分支都有 `pause`。

**页面 404 / 空白**
确认 `frontend/dist/index.html` 或 `controller-web/web_dist/index.html` 存在。缺失说明拷贝时被过滤，重新拷这两个目录。

**Edge 没自动打开**
`tools/open_ui.ps1` 找不到 Edge 时会退回默认浏览器；也可以手动打开脚本打印的 URL。企业机器若禁用 PowerShell 脚本，执行策略改为 `RemoteSigned` 即可。

**端口被占用**
`netstat -ano | findstr ":8000"` 找到 PID 后结束进程，或改脚本里的 `BACKEND_PORT` / `PORT`。

**Controller 读不到 Runner 的货架**
两个工程不同级时执行：`set ATE_ASSISTANT_SHELF=<Runner>\backend\assistant_shelf`，再跑 `python seed_assistants.py`。
