01

模版与放置位置

模版描述的是「注册库里的一条设备记录」，不是一棵新树——设备永远挂在某台测试台下。

文件 ate-device-template.jsonc 用 JSONC 写法（// 后为备注），去掉注释后就是合法 JSON，可直接进 backend/testresource/testbenches.json 的 testbenches[].devices[]。新建设备时不必手写：在「测试台注册 → 类型选型」里选定预设类型，平台会把该类型的标准 BOM（testbench_presets.json）预填进来，现场只需要改连接参数。

字段口径来自三处：注册库读写与校验（testbench_registry.py 的 DeviceConfig、_device_configured、DeviceConfigPatch）、驱动自动匹配（drivers/factory.py 的 DRIVER_SPECS）、以及实际注册样本（testbenches.json）。模版的 18 个字段与注册库实际记录的字段完全一致，无缺无多。

02

最小可用条目

被动设备四个字段即可；程控设备在此基础上按接口类型补齐连接参数。

// 仅登记、不程控（夹具 / 探头 / 工装）
{
  "id": "rh-fixture",           // 台内唯一别名，TPS 用它引用
  "name": "读头装夹夹具与探针组",  // 显示名
  "programmable": false,        // 不可程控
  "interface": "NONE"           // 无程控接口，自检记 skip
}

程控设备必须按接口类型补齐连接参数：网络类给 host + port，串口类给 serial_port，USB / GPIB 类给 address；同时把 model、vendor、category、role 填准，平台才能挂对驱动。

03

字段参考

按作用分五组。带 必填 的字段缺失会被注册自检拦下；标「只读」的由平台计算，不要手填。

①标识与识别

决定这台设备在平台里叫什么、被谁引用。

字段类型必填作用示例
idstring必填设备别名，同一测试台内唯一。TPS 的 device_config 用它引用设备（device_id）rh-scope
namestring必填中文显示名，出现在装备树、装备助手工具卡片与测试报告中；参与驱动匹配（权重 1.0）数字示波器
modelstring必填型号全称。驱动自动匹配的最高权重字段（3.0），写错会挂到错误驱动上Tektronix MSO54
vendorstring必填厂商名，驱动匹配权重 2.0Tektronix
categorystring必填设备类别（示波器 / 万用表 / 电源 / 电子负载 / 信号源 / 运动控制 / 数据采集 / 被动设备…），驱动匹配权重 2.0示波器
rolestring必填这台设备在本测试台上的用途，驱动匹配权重 1.5；同款设备用途不同时靠它区分读头回放信号波形 / 边沿与噪声观测

②程控与接口

决定平台怎么连它、能不能程控。

字段类型必填作用示例
programmablebool必填是否可编程。false = 被动设备（夹具、探头、工装），只登记、不参与通讯自检true
interfaceenum必填接口类型，决定「配置完整」的判定方式与自检手段，取值不区分大小写、入库统一转大写LAN

③连接参数

注册之后唯一允许修改的一组字段（型号、厂商、类别、用途不允许改）。

字段类型必填作用示例
hoststring网络类必填设备 IP 或主机名。建议为仪器分配固定 IP（DHCP 保留），否则换网后注册库里的地址会失效192.168.10.41
portint网络类必填端口号 1–65535。常见值 4000=VXI-11、5025=SCPI raw socket、3490=Fluke 万用表、30000=ITECH 电源/负载4000
serial_portstring串口类必填串口号，如 COM6。Windows 下换 USB 口会变号，接入前确认设备管理器里的实际编号COM6
baudrateint可选波特率，如 115200。留空时平台按设备默认值尝试115200
addressstringUSB / GPIB 必填VISA 资源串。网络设备可填（便于 VISA 通道复用），USB / GPIB 设备必须填，NONE 类留空TCPIP0::192.168.10.41::inst0::INSTR
channelstring可选默认通道 / 端口号。多路电源、开关单元用它标明默认通道CH1
protocolstring可选协议说明，写给人看，不参与自检判定VXI-11 (SCPI)

④管理与约束

决定注册自检会不会被拦下。

字段类型必填作用示例
requiredbool必填是否必备设备。必备且 programmable 的设备若未配置完整，注册自检报 fail 并阻断注册true
notestring可选备注。建议写固定 IP 要求、量程 / 带宽、校准周期、负责人等排障时要看的信息8 通道；建议固定 IP

⑤系统回写

由平台计算，请勿手工填写。

字段类型必填作用示例
configuredbool只读平台按 interface 判定配置是否完整：网络类看 host + port，串口类看 serial_port，其余看 addresstrue
04

接口类型与配置完整判定

interface 不只是描述——它直接决定平台判不判这台设备「配置完整」、以及用什么手段自检。

interface 取值类别必填连接字段配置完整判定自检方式
LAN / ETHERNET / TCP / IP网络类host + porthost 非空 且 port 有值TCP 探测（真实模式）；仿真模式记模拟自检
SERIAL / RS232 / RS485 / UART / COM串口类serial_portserial_port 非空串口探测（真实模式）
USB / GPIB / MANUAL / NONE不自动探测address（其余留空）address 非空记 skip，需人工确认连通性

判定逻辑与 _device_configured() 一致：网络类要求 host 非空且 port 有值；串口类只看 serial_port（baudrate 留空不阻断）；USB / GPIB / NONE 以 address 是否登记为准，连通性仍需人工确认，自检结果记为 skip 而不是 fail。

05

注册后可改 / 只读

注册库是唯一事实源：设备属性配置页只写回连接参数，BOM 元信息不允许改，改动可追溯、可单项恢复。

可改 · 连接参数

  • host
  • port
  • protocol
  • serial_port
  • baudrate
  • address
  • channel
  • note

只读 · BOM 元信息

  • id
  • name
  • model
  • vendor
  • category
  • role
  • programmable
  • interface
  • required

改连接参数的接口是 DeviceConfigPatch（另带 reset_defaults 可一键恢复为该预设类型 BOM 的默认连接值）。同一测试台内两设备地址重复会被拦截：注册自检报 address_conflict，设备属性配置保存时还会二次校验。

06

驱动自动匹配规则

平台不要求登记驱动名，而是按字段关键字打分自动挂驱动；所以型号 / 厂商 / 类别 / 用途这四个字段要填准。

优先级驱动 key覆盖设备匹配关键字
20tektronix-mso5示波器model: mso5 / mso54 / mso64 / dpo5 / tektronix；vendor: tektronix
14serial-motion运动控制器category: 运动控制 / motion / 转速 / spin；interface: SERIAL / RS232 / RS485 / UART / COM
12generic-dmm数字万用表category: 万用表 / dmm / multimeter；role: dmm / 万用表
12generic-psu可编程直流电源category: 电源 / psu / power supply；role: psu / 电源
12generic-eload可编程电子负载category: 电子负载 / eload / load；role: eload / 负载
12generic-awg波形发生器 / 信号源category: 信号源 / 波形 / awg / generator；role: awg / 信号源
5passive-device被动设备（无通讯）interface: NONE / MANUAL / USB / GPIB
1generic-scpi通用 SCPI 仪器（兜底）match 为空：上面全部未命中时回落至此

打分权重：model 3.0、vendor 2.0、category 2.0、role 1.5、interface 1.2、name 1.0；每个字段只要命中一个关键字就加分，取总分最高的驱动，同分时取优先级更高者；全部未命中则回落到 generic-scpi 兜底。

用模版里的三个示例复算过：网络示波器命中 tektronix-mso5（5.0 分）、转速控制盒命中 serial-motion（3.2 分）、夹具命中 passive-device（1.2 分）。

07

预设 BOM 与注册库的字段映射

预设 BOM 用 default_ 前缀表达「默认值」，注册时由 _devices_from_preset() 摊平成注册库字段。

预设 BOM（testbench_presets.json）注册库（testbenches.json）说明
id / name / model / vendor / category / role同名直传BOM 元信息，注册后不可改
default_hosthost预填默认 IP，现场按实际改
default_portport预填默认端口
default_serial_portserial_port预填默认串口号
default_baudratebaudrate预填默认波特率
default_addressaddress预填 VISA 资源串
default_channelchannel预填默认通道
—（预设 BOM 中不存在）configured注册时由平台按接口类型计算
08

常见的五类错误

这五条覆盖了现场接入时绝大多数注册失败与「设备连不上」的报障。

现象原因处理
注册自检 fail：必备设备未配置programmable=true 且 required=true，但按接口类型所需字段为空网络类补 host + port，串口类补 serial_port；其余补 address
注册自检 fail：设备地址冲突同一测试台内两台设备用了相同的 IP + 端口改端口或换设备 IP；设备属性配置环节也会二次拦截
设备拿不到工具卡片 / 控制不了驱动自动匹配落到 generic-scpi 兜底，或挂到邻近驱动上检查 model / vendor / category 的拼写与关键字是否命中驱动规格表
串口类设备时通时不通USB 转串口换插口后 COMn 变化固定 USB 插口，或改用串口服务器并固定端口号
换网络环境后连不上仪器使用 DHCP 动态地址，注册库里的 host 已失效为仪器配置 DHCP 保留或静态 IP，再到设备属性配置里更新 host
09

与 TPS 的衔接

TPS 侧不重复登记设备，只用别名引用——注册这台设备的意义就在这里。

TPS 的 device_config 里每个功能槽写 device_id（即设备注册的 id）、role 与 note；运行前平台把它与注册库设备清单交叉核对，缺设备或契约版本不匹配会阻断运行并给出补齐清单，无实机时可走仿真通道并明确标注。设备注册的 id 一旦改名，所有引用它的 TPS 都要同步改。

10

字段保留策略

要不要每台设备只留自己接口相关的字段？结论：存储层保留全部 18 个字段（与接口无关的留空占位），表单、校验与提交层按 interface 只处理相关字段——两侧都不裁剪存储结构。

推荐 · 全字段存储 + 表单按接口裁剪（当前实现）

  • 一份 DeviceConfig 模型覆盖所有设备，注册库 / TPS 契约 / 导出 / 报告共用同一套键，读方不用分支
  • 接口临时改动（把网口设备借来试串口）不会丢掉原有 host / port
  • 空值语义明确（字符串 ""、数字 null），_device_configured 按接口只看该看的字段，空值不误判
  • 代价：每台设备多带几个空键（一台几十字节），阅读噪音由表单层吸收

不推荐 · 按接口裁剪存储

  • 表面收益：单条记录更短、看着干净
  • 读方（校验 / 导出 / 报告 / 联调脚本）都要按接口分支
  • 换接口会丢值；「键不存在」与「被清空」无法区分
  • 预设 BOM、注册库、TPS 三处 schema 容易漂移，文件 diff 与评审按设备各异

真实注册记录印证了这一点：LAN / SERIAL / NONE 三类设备都是同一组 18 个键——网口示波器带 "serial_port": "" 与 "baudrate": null，串口转速盒带 "host": "" 与 "port": null，夹具则是全部连接字段留空。而前端 payload() 只提交本接口分支的键。字段按接口的适用性如下：

字段LAN 网络类SERIAL 串口类USB / GPIBNONE 被动说明
元信息 10 项：id / name / model / vendor / category / role / programmable / interface / required / note必填必填必填必填与接口无关，所有设备一致，注册后只读（note 可改）
host必填不适用不适用不适用IP / 主机名；网口类判定「配满」的必要项
port必填不适用不适用不适用端口；网口类判定「配满」的必要项
serial_port不适用必填不适用不适用串口号；串口类判定「配满」的唯一必要项
baudrate不适用选填不适用不适用留空按设备默认值尝试，不阻断判定
address选填（VISA 通道复用）选填必填不适用VISA 资源串；USB / GPIB 以它判定「配满」
channel不适用不适用选填不适用多路电源 / 开关单元的默认通道
protocol选填选填选填不适用协议说明，写给人看，不参与判定
configured系统回写系统回写系统回写系统回写平台按接口计算的配置完整标记，只读

表单侧不是「隐藏字段」，而是按接口分组提交——这也是 DeviceConfigPatch 只接受连接参数的原因：

interface 分支提交键校验规则
网络类（LAN / ETHERNET / TCP / IP）host / port / protocol + noteIP 或主机名非空且格式合法；端口为 1–65535 整数
串口类（SERIAL / RS232 / RS485 / UART / COM）serial_port / baudrate / protocol + note串口号形如 COM3 合法性校验；波特率 300–1000000（留空不报错）
其余（USB / GPIB / MANUAL / NONE）address / channel / protocol + note仅当 programmable 时要求资源地址非空；通道与资源地址做字符集校验

落地三条：① 注册库永不裁剪，所有设备写满 18 键，空值统一 "" / null；② 需要「干净」外观时只在导出 / 展示层裁剪（导出可加 omit_empty，报告与页面按接口只渲染相关字段）；③ 确实要改存储形态时，必须同步改 DeviceConfig、_devices_from_preset、_device_configured、TPS 契约与全部读方，不建议。

//           新建设备时由「测试台注册 → 类型选型」把预设 BOM（testbench_presets.json）
//           预填进来，现场只改连接参数。

//          、backend/testresource/testbenches.json（实际注册样本）
// 维护    ：字段增删须同步 registry / 前端表单 / 本模版三处
// =============================================================================
{
  "schema": "ate.device.registration.v1",   // 模版版本标识：字段结构变更时递增尾号
  "updated_at": "2026-09-16",               // 本模版最后修订日期（YYYY-MM-DD）

  // ===========================================================================
  // 一条设备条目：下列字段即注册库 devices[] 的一条记录（扁平结构，无嵌套）
  // ===========================================================================
  "device": {

    // ---------- ① 标识：决定这台设备在平台里叫什么、被谁引用 ----------

    "category": "示波器",                    // 【必填】设备类别（示波器/万用表/电源/电子负载/信号源/运动控制/数据采集/被动设备…）。驱动匹配权重 2.0
