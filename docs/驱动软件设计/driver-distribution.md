# 驱动在线分发方案（仅在线）

**状态**：设计定稿（替代 2026-09-13 版《驱动分发》）
**适用范围**：ATE Runner 的驱动包（`.atepkg`）获取、校验与更新
**前提**：目标机器可访问内网 HTTP 仓库或 MES 分发服务；不提供 U 盘、共享盘拷贝等离线导入路径。

## 一句话结论

驱动只从**受控在线仓库**分发：仓库发签名索引，Runner 拉索引、比版本、验签、下载、装包；生产台架锁定版本，不自动追最新。

## 1. 为什么不保留离线分发

离线介质无法证明"包从哪来、有没有被改过、是不是最新批准版本"。一旦允许 U 盘导入，签名校验就退化成"有个签名文件就行"，而现场无法区分正式包和临时改过的包。

在线分发把三件事绑在一起：**来源可鉴权、内容可校验、版本可追溯**。

## 2. 三种在线拓扑

| 拓扑 | 做法 | 适用 | 注意 |
|---|---|---|---|
| 工位直连 | Runner 访问车间 HTTP 仓库的 `index.json` 与包 | 单台或少量工控机 | 断网时只读本地缓存，不静默降级 |
| 车间镜像 | 车间内一台镜像服务同步总部仓库，工位指向镜像 | 多台 Runner、跨网段 | 镜像只做透传，不改包、不重签 |
| MES 推送 | MES 按台架台账推送指定版本，Runner 只接受推送 | 多产线、统一版本 | 推送需审批记录，失败要回执 |

三种拓扑共用同一个包格式和同一套校验，区别只在"包从哪个地址来"。

## 3. 索引与包

仓库根目录提供 `index.json`：

```json
{
  "schema": "ate.driver.index.v1",
  "generated_at": "2026-10-18T10:00:00+08:00",
  "channel": "prod",
  "packages": [
    {
      "key": "tektronix-mso5",
      "version": "1.6.0",
      "api": "1.2",
      "min_platform": "1.0.0",
      "models": ["MSO54", "MSO56", "MSO58", "MSO64"],
      "url": "packages/tektronix-mso5-1.6.0.atepkg",
      "sha256": "…",
      "size": 48213,
      "signature": "…"
    }
  ]
}
```

约束：

- 索引本身也要签名，Runner 先验索引、再信其中的包哈希；
- `url` 必须是相对路径或同域 HTTPS 地址，禁止跨域任意地址；
- 同一 `key` 可列多个版本，但必须有一个 `latest` 标记，生产默认不用它；
- 索引只追加，不覆盖历史版本条目，否则无法解释"上周装的是什么"。

## 4. 客户端行为

1. 读取配置的仓库地址与受信公钥；
2. 拉 `index.json`，验签，写入 `drivers/.cache/index.json`；
3. 与本地 `installed.json` 比对，列出可升级项；
4. 用户或 MES 选择版本后，下载包到 `.incoming/`；
5. 校验 `sha256` 与包内 `SHA256SUMS`、`SIGNATURE`；
6. 校验 `api` / `min_platform`，检查型号冲突；
7. 解包到版本目录，写状态，激活或仅登记；
8. 全过程写 `audit.log`。

断网时：只读缓存索引，不发起请求，不提示"检查更新失败"以外的降级动作。

## 5. 失败与回退

| 失败点 | 行为 |
|---|---|
| 索引验签失败 | 拒绝使用整份索引，保留上次缓存 |
| 包哈希不符 | 丢弃下载文件，记 `E_PKG_HASH` |
| 签名不符 | 丢弃，记 `E_PKG_SIGNATURE` |
| 兼容不满足 | 不下载或下载后拒装，记 `E_PKG_COMPAT` |
| 型号冲突 | 拒装，记 `E_PKG_CONFLICT` |
| 装后派发失败 | 自动回滚到上一 active 版本，记审计 |

回滚只切 `active.json` 指针，不重新下载、不重新解包。

## 6. 运维要点

- 发布机持有私钥，仓库只存公钥与包；
- 每个 channel（prod / staging）独立索引，生产不读 staging；
- 台架锁定 `key + version`，升级是显式动作；
- 至少保留 N-1 版本，卸载前检查台架锁；
- 审计日志含操作者、来源地址、包哈希、前后版本。
