00

摘要与边界

Design position

内核只负责稳定语义，不负责型号覆盖。

内置驱动内核是 Runner 安装包内的最小驱动运行环境。它定义“驱动必须长什么样、如何被派发、如何打开、如何返回结果、如何安全关闭”，但不承载具体型号的协议差异，也不承担设备发现、业务判定和界面展示。

目标 01

单一契约

TPS 只依赖能力名与返回结构，不接触 SCPI 命令、寄存器地址或厂商方言。

目标 02

单向依赖

门面、注册表、家族、链路、传输逐层向下；厂商包只依赖家族与契约，不得反向引用平台。

目标 03

实现可替换

型号实现可以独立发布；替换实现不改变动作名、单位、错误码与结果结构。

当前实现与目标契约

维度当前 backend/drivers目标 sdk/ate_drivers本文要求
选型DRIVER_SPECS 按字段权重打分，同分比 priority，最后回落 generic-scpi型号归一化后精确查表，未命中报 E_NOT_FOUND生产运行时统一为精确派发；打分仅作为旧档案兼容层
契约Driver.do() 返回 9 个键，动作名为短名InstrumentDriver.do() 返回 16 个键，能力名为点分命名空间新驱动按 1.2 契约开发；旧短名经 ALIASES 过渡
家族scope.py / scpi.py 内直接包含命令与算法family/scope.py 定义语义与单位，vendors 只填差异面厂商包不得复制家族算法，不得修改动作语义
运行时接入conftest 直接 from drivers import get_driver提供同形 get_driver 适配器，内部走 SDK 注册表TPS 导入路径不变，行为切到新内核
货架无外置扫描；工厂表硬编码kit.registry 已提供 scan_dir / merge_specs / resolve_spec内核只消费合并后的注册表，不直接管理安装

结论：本文以 sdk/ate_drivers 的契约口径为目标态，以 backend/drivers 为兼容现状。当前不是“从零设计”，而是“把已存在的 SDK 契约接入生产运行时”。

非目标

内核不负责

  • 设备发现：不扫网段、不枚举串口；设备档案是唯一事实源。
  • 业务判定：合格/不合格、阈值与报告由 TPS 与 Runner 负责。
  • 货架生命周期：下载、验签、安装、回滚由货架管理组件负责。
  • UI 与权限：工具卡片、驱动库页面、操作员授权在平台侧。

内核必须负责

  • 驱动元数据、能力声明、动作分发的统一约束。
  • 端点解析、传输选择、真实/仿真分叉。
  • 会话打开、识别、安全退出与资源释放。
  • 型号派发、别名、版本兼容与错误分类。
01

范围与术语

术语定义本文中的边界
驱动内核随 Runner 发布的驱动运行环境与稳定契约层包含 base、contract、capabilities、models、errors、endpoint、transport、family、registry、facade
家族一类仪器的共同语义，如示波器、万用表、电源定义动作、单位、算法、仿真基线；不出现具体品牌命令
厂商包某品牌/型号的命令表、应答解析、缩放与仿真差异只填差异面；不得改动作名、单位、返回结构
驱动货架Runner 外部可安装的驱动包集合与生命周期管理不在本文展开；内核只接收其合并后的清单
端点一台仪器的物理连接描述：LAN 或 SERIAL只描述“怎么接”，不描述“用哪套客户端栈”
传输后端实际收发字节的实现：native 或 visa与端点正交；实际值必须可查询、可记录
TPS测试程序集，调用驱动完成测量与判定只依赖能力接口；不得 import 厂商包内部模块
契约版本驱动与平台之间的 API 兼容版本，当前为 1.2major 必须相等；minor 只增不减

范围判定

In scope

  • 内核分层、依赖方向、对象职责。
  • 型号派发、会话生命周期、错误模型。
  • 真实/仿真一致性、单位与返回结构。
  • 内核的构建、打包、测试与迁移。

Out of scope

  • 驱动包签名算法与安装事务。
  • 货架目录、索引服务、集中分发。
  • 设备注册表字段设计与迁移脚本。
  • 前端驱动管理页面与权限模型。
02

逻辑视图

逻辑视图描述内核的职责分区与协作关系。依赖方向固定为自上而下；任何下层模块不得反向 import 上层，厂商包不得 import 其它厂商包。

2.1 分层职责

层职责允许依赖禁止事项
门面层参数校验、模式选择、型号核对、结果整理注册表、家族、端点出现任何仪器命令字符串；让 TPS 直接构造传输
注册表层型号归一化、登记、精确派发、别名、冲突检测、清单合并家族、契约按关键字打分；模糊匹配；未命中时回落到“最像的驱动”
家族层动作名、参数单位、测量算法、默认仿真、安全退出base、contract、capabilities出现具体品牌命令；把厂商差异写进家族
厂商包命令表、应答前导、量纲缩放、枚举映射、仿真差异家族、契约修改动作语义；import 其它厂商包；访问数据库
端点层档案到 Endpoint；LAN/SERIAL；后端解析；参数校验models、errors猜链路；静默降级；把波特率拼进 VISA 资源名
传输层open/close/write/read/query；真实与仿真分叉errors、models把 pyserial / pyvisa 变成硬依赖；泄漏协议语义
底座会话、动作分发、能力校验、错误码、数据模型仅标准库依赖家族以上任何模块

2.2 核心对象

对象来源职责生命周期
DeviceConfigSQLite 设备行 / TPS 覆盖型号、端点、角色、超时、后端的只读投影每次派发创建；不缓存连接状态
Endpointendpoint_from()LAN/SERIAL 的规范化连接描述与一次会话绑定；关闭后不重用
DriverSpec内置规格 + 货架清单型号、入口、版本、能力、接口、后端启动时合并；安装/激活后重建
InstrumentDriver注册表派发的类会话、动作、能力、仿真、安全退出open() 到 close()；可重开
Transportmake_transport()字节收发；超时；资源释放由驱动持有；关闭时释放
Capabilitycontract / capabilities能力名与家族基线；动作映射的依据类级常量；不可实例化修改

2.3 典型协作序列

# 启动阶段：只合并清单，不 import 所有驱动
specs = merge_specs(builtin_specs, scan_dir(driver_root))

# 每次设备派发
cfg    = DeviceConfig.from_dict(device_row)
spec   = resolve_spec(cfg.model, specs)       # 精确匹配；未命中 E_NOT_FOUND
cls    = resolve_entry(spec)                  # 此时才 import 驱动模块
driver = cls(cfg, mode=mode, backend=cfg.backend)
driver.open()                                 # 建链 + *IDN? + 型号核对
result = driver.do("scope.measure", items=("PK2PK", "FREQUENCY"))
driver.close()                                # 安全退出 + 释放链路

2.4 会话状态

状态进入条件允许操作退出
DECLARED驱动实例已构造，尚未建链读取元数据、能力、状态open() → OPENING；close() 幂等
OPENING传输层正在连接仅内部操作成功 → READY；I/O 失败 → FAILED
READY链路已建立，身份已读取全部已声明动作动作失败保持 READY；close() → CLOSED
FAILED建链失败或不可恢复错误读取错误、关闭重新 open() 可重试；否则 CLOSED
CLOSED已下发安全退出并释放链路读取历史状态可重新 open()

动作级错误不改变会话状态；只有链路级错误才进入 FAILED。这样 TPS 可以在同一会话内对参数错误做修正并重试，而不必重新建链。

2.5 设计不变量

语义不变量

  • 型号是派发唯一依据；型号为空或未登记即失败。
  • 同一型号只能映射到一个驱动 key；冲突必须在激活前拒绝。
  • 动作名、单位、返回结构由家族定义；厂商包不得改写。
  • 所有物理量使用 SI 基本单位；缩放只发生在厂商包内部。

运行时不变量

  • 真实与仿真返回同一结构；仿真结果必须可复现。
  • 实例状态只挂在实例上；不得使用可变类属性保存会话数据。
  • close() 必须先执行安全退出命令，再释放链路。
  • 实际传输后端必须可查询、可写入运行记录，不得静默切换。
03

运行时协作

运行时只做四件事：把设备档案投影成 DeviceConfig，把型号解析成驱动规格，把规格实例化为驱动，把驱动生命周期交给 TPS。内核不持有全局设备清单，也不在后台轮询仪器。

3.1 启动与派发

  1. 01

    加载内置规格

    从 builtin_specs 读取随包发布的驱动规格；不 import 驱动实现，只保留 key、型号、入口、能力与版本。

  2. 02

    合并货架清单

    调用 scan_dir 读取已安装包的 driver.json，由 merge_specs 合并。单个坏包只标记不可加载，不阻断启动。

  3. 03

    检测冲突

    启动时执行 model_conflicts；同型号被不同 key 声明时，拒绝激活并给出双方 key，不做隐式选择。

  4. 04

    按型号解析

    resolve_spec 只做归一化后的精确匹配；未命中时返回 E_NOT_FOUND 和可用型号列表。

  5. 05

    实例化并打开

    按入口 import 驱动类，传入 DeviceConfig、模式和显式后端；open() 建链并读取身份。

  6. 06

    释放

    会话结束统一调用 release_all() 或上下文管理器退出；每个驱动先执行安全退出，再关闭传输。

3.2 TPS 侧边界

当前 backend/tps_runtime/conftest_template.py 直接执行 from drivers import get_driver。目标态保留这个导入形状，只把实现替换为内核适配器，避免 TPS 因内核迁移而改写。

# 目标适配器：保持旧调用形状，内部走新注册表
from ate_drivers.runtime import get_driver

driver = get_driver(
    device_row,              # SQLite 行或 dict
    mode="real",             # real | simulate
    alias="scope_main",
    backend="native",        # 可省略；省略时按档案
)
with driver:
    result = driver.do("scope.measure", items=("PK2PK", "FREQUENCY"))

适配器只负责参数归一、注册表解析和实例缓存；不得在适配器内实现协议差异，也不得让 TPS 看到 DriverSpec 或厂商模块路径。

3.3 错误映射

错误码触发场景TPS 可见行为是否重试
E_CONFIG端点缺失、IP/端口不成对、链路歧义、型号与 IDN 不符用例失败，提示修档案或接线否
E_NOT_FOUND型号未登记、驱动包缺失用例失败，列出可用型号否
E_TRANSPORT连接失败、写失败、串口打不开用例失败，保留链路细节可重试一次
E_TIMEOUT读写超时用例失败，记录超时值可重试一次
E_PROTOCOL应答无法解析、字段缺失、前导不匹配用例失败，提示方言/固件否
E_UNSUPPORTED调用了未声明能力用例失败，列出已声明能力否
E_CONTRACT驱动 API 与平台不兼容加载阶段失败，不进入用例否
E_PARAM参数越界、枚举未登记用例失败，保留原始参数否

3.4 仿真契约

仿真不是“没有硬件时的临时分支”，而是内核的一等运行模式。它必须满足三条：不访问真实链路；同一输入产生同一输出；返回结构与真实模式一致。这样 TPS 可以在离线环境完成阈值逻辑、报告渲染和异常分支验证。

约束仿真结果不得使用全局随机源或当前时间做种子；不得因为缺少硬件而返回与真实模式不同的键集合；不得把仿真专用字段泄漏到 TPS 业务判断中。

4.5 驱动类契约

class InstrumentDriver:
    driver_key: str          # 稳定标识，形如 vendor-model

05

契约与兼容

兼容性必须在加载阶段判定，不允许“先 import 再报错”。契约版本采用 major.minor：major 表示破坏性变更，minor 只表示向后兼容的扩展。

规则判定失败行为
major 相等驱动 api 的 major 必须等于平台 API_VERSIONE_CONTRACT，拒绝加载
minor 不高于平台驱动 minor ≤ 平台 minor提示升级平台，拒绝加载
min_platform平台版本 ≥ 驱动声明的最低版本拒绝安装/激活
动作只增不减新增动作、能力、detail 键；不删除、不改名破坏性变更必须升 major
弃用过渡弃用项给出替代动作与移除版本，至少跨一个 minor门禁 C16 失败
旧动作ALIASES 保活历史 TPS未知动作 → E_UNSUPPORTED
当前基线API_VERSION = "1.2"，RESULT_SCHEMA = "ate.driver.result.v1"，WAVEFORM_SCHEMA = "ate.driver.waveform.v1"，MANIFEST_SCHEMA = "ate.driver.manifest.v1"。这些常量是跨版本判定的唯一依据，不得由驱动包自行复制。

演进与验收

7.1 迁移路径

阶段动作兼容策略退出条件
K0 契约对齐以 SDK 的 contract / base / capabilities 作为目标契约；旧 backend/drivers 保留TPS 导入路径不变契约测试通过，旧 TPS 全绿
K1 注册表接入get_driver 适配器内部改为 scan_dir → merge_specs → resolve_spec旧 DRIVER_SPECS 转成内置 specs；短名映射到能力名型号派发一致；未登记型号按预期报错
K2 家族统一示波器先切到 family/scope + vendors；其它家族按同模式迁移旧 scope.py 仅作为兼容实现真机/仿真结果一致；门禁 19/19
K3 移除打分删除 _score 与 priority 兜底；保留显式别名设备档案型号先清洗；旧记录可回读无未登记型号依赖模糊匹配

7.2 验收判据

  • 单一入口：TPS 只通过能力接口调用，不出现 SCPI 字符串。
  • 精确派发：同一型号只命中一个 key；未登记型号明确失败。
  • 契约一致：真实与仿真返回同一组键、同一单位。
  • 链路平权：LAN / SERIAL 只改档案，不改业务代码。
  • 后端可查：native / visa 实际值写入结果与日志。
  • 安全退出：关闭会话执行已登记的保护命令。
  • 实例隔离：两个驱动实例不共享可变状态。
  • 兼容可控：API major 不等时加载阶段拒绝。
  • 迁移可回退：旧 get_driver 路径在适配期内可用。
  • 构建可复现：同版本内核与驱动包产出同结构产物。
