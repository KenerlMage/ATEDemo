ATE Runner · 驱动软件设计 · 决策备忘

底层已被 RsInstrument / pypylon 封装，连接层还留不留

结论先说：要删的是「自己写协议实现」这件事，不是「连接抽象」这一层。把连接层从自研实现降级为一份契约加若干适配器，代码量掉一大半，而仿真、换后端、离线跑 TPS 这些能力全部保住。

适用范围 · ATE Runner 驱动子系统（sdk/ate_drivers） 日期 · 2026-11-08 结论强度 · 建议采纳
Verdict

保留 Transport 契约，砍掉自研的链路实现（socket / 串口 / VISA 会话管理），把 RsInstrument、pypylon、pyvisa 一律收进适配器层。

理由不是「抽象好看」，而是这三个能力厂商库永远不提供：真实与仿真同构（同一份驱动无硬件也能跑）、设备档案到资源名的解析、整条链路的可替换与可观测。这三个一旦散进驱动代码，就再也收不回来了。

01先把「连接层」拆成三件事

争「要不要连接层」之所以吵不清，是因为大家说的不是同一件事。三件职责的归属必须分开看。

职责归属
职责具体内容谁来做SDK 库代劳后还需要你写吗
会话建立 TCP、串口、VISA 会话、GenICam 流通道、超时与重连 RsInstrument / pyvisa / pypylon 不需要 —— 这正是它们的核心价值
命令语义 *IDN?、测量命令、曝光/增益节点、错误队列 驱动家族层（scpi.py / camera.py） 不需要 —— 本来就属于驱动，不属于连接层
运行形态与替换 仿真链路、离线回放、测试替身、后端切换、连接统计与自检 你自己的连接契约 需要 —— 厂商库不管「没有硬件怎么跑」

第三行就是连接层存在的真正理由。它不是「帮驱动连设备」，而是「让驱动在连不上设备时也能被测试」。把这条想清楚，「要不要」的问题就变成了「留多大」。

02三个方案，只有中间那个站得住

「全删」听起来最干净，但它把成本从连接层转移到了每个驱动和每次 CI 上。

方案对比

03你的代码已经跑通了两个范式

这不是纸上推演 —— 两条相反的路径都已经在仓库里落地，而且都对。

已落地的两种形态
实现做法说明什么
RsInstrumentLink 把 RsInstrument 会话包成 Transport，对外仍是 open / write / query；缺 RsVisa 时回落到标准库 socket 文本命令面（SCPI）完全可以统一到一条字节管道，驱动对厂商库无感
BaslerPylonCamera 不经过 make_transport()，直接持有 InstantCamera；CameraChannel 只把动作记进日志 帧数据面（流、缓冲、抓取状态机）不该被硬塞进请求-响应模型

这两条放在一起才是完整答案：连接层不是「所有设备共用一个字节管道」，而是「同一类数据面提供同一个可替换的调用面」。强行统一到 read/write，只会在 _read_line 里长出 if camera 分支，比不做更糟。

04目标分层：L0 只剩契约

下面这四层是收敛后的形态。关键变化在 L0 —— 它不再实现任何协议，只定义「怎么接」。

L0
连接契约 · Transport 接口 + SimulateTransport + endpoint 资源解析 + make_transport 分叉
不做协议，不认厂商
L1
链路适配器 · rs_link（RsInstrument）、voyager/visa、socket / serial 回退、pylon_link（相机会话）
每支适配器几十到一百行
L2
驱动家族 · scpi.py 文本命令族、camera.py 帧数据族，只依赖 L0 契约
不认识任何厂商库
L3
厂商驱动 · rohde_schwarz_mxo、basler_pylon 等，SDK 只允许出现在这一层
可整体卸载不影响别家

判据一句话：SDK 出现在 L0 就是漏层，出现在 L2 就是越层，只有 L1 / L3 合法。现在 RsInstrumentLink 放在 vendors 下、transport.py 用 set_visa_factory 注入后端，已经符合这条线，剩下的是把文档和命名对齐。

05什么时候可以真的删掉

给未来的自己三条硬判据。三条同时为真，连接层就该退化成三十行工厂函数；现在三条都不成立。

  • 驱动源码里 grep 不到厂商库除 L1 适配器与 L3 厂商驱动之外，任何文件出现 import RsInstrument / pypylon 都算判据失败。
  • 资源名拼接全部在 endpoint驱动里不出现 host:port、ASRL3::INSTR、TCPIP0:: 这类字符串，只拿设备档案。
  • 无硬件环境能跑完整 TPS 且全绿CI 里没有任何真实仪器，用例仍然过 —— 这说明仿真链路还在，删掉连接层就做不到这条。

06落地动作

  1. 给 L0 改名定性transport.py 的模块说明写死一句：本层只定义契约，不实现任何厂商协议。避免下一个人继续往里加 VISA 细节。
  2. 厂商库只准进 L1 / L3RsInstrument、pypylon、pyvisa 的 import 收敛到 links/ 与 vendors/，其余层一律通过契约调用。
  3. socket / serial 标为回退链文档写明适用场景：没有 RsVisa 的现场、私有文本协议老设备、继电器板这类 RS485 器件。不是主路径，但别删。
  4. 相机改用会话抽象相机需要的是 open / close / state / acquire 四件事，不是 write / read。定义 DeviceSession，把 pypylon 的抓取状态机封在里面，上层的取帧代码一行不用改。
  5. 补一条 conformance 测试同一支驱动分别在 simulate、真实适配器、回退链三种链路下跑同一组断言，行为必须一致。kit/conformance.py 已有骨架，缺的是把三种链路都纳进矩阵。

07代价摆清楚

删掉连接层的隐性成本

  • CI、培训、客户演示没有硬件时全部失效，只能靠录制回放补
  • 换 VISA 后端（RsVisa / NI-VISA / pyvisa-py）要动所有驱动
  • 现场缺 R&S VISA 时没有回退，故障从「能跑」变成「装环境」
  • 连接统计、自检、超时策略会散落到各驱动，无法统一调

保留契约的成本

  • 一层薄抽象，契约本身约两百行，理解成本低
  • 契约一旦变更要同步所有适配器，需要版本纪律
  • 排障多一跳：要先确认走的是哪条链路（用 describe() 能直接看出来）
结论：连接层保留为契约，实现交给适配器 ATE Runner · 驱动软件设计
