01

范围与口径

本文描述运行期驱动包：随 ATE Runner 安装包发布、位于 app/drivers 的 8 类驱动，以及驱动包与平台、SDK、部署形态之间的关系。视图采用架构描述常用的逻辑视图、开发视图、部署视图三视角，功能点作为逻辑视图的输入。

项口径
包边界运行期驱动包 = app/drivers；SDK（sdk/ate_drivers）不进入安装包
版本口径驱动集合版本 = Runner 版本，无独立驱动版本号
功能点计数以 ACTIONS 键为准，8 类合计 64 项
部署单位整包 app/ + web/ + runtime/，无单驱动安装单元
数据边界logs / workspace / testresource / ate.db / license.dat 为保留项，升级不覆盖

03

逻辑视图

逻辑视图描述职责与协作，不涉及文件位置。分五层，上层只能依赖相邻下层。

L1 用例层
TPS 步骤、测试工具页
L2 门面层
AteContext、do() / supports()
L3 派发层
resolve_spec / resolve_driver_class
L4 驱动层
家族基类 + 8 类驱动 + ACTIONS
L5 传输层
simulate / socket / serial / visa

调用链固定为一条：用例给出设备别名与动作名，门面层补默认参数，派发层按 device_type 取出实例，驱动层解析动作到方法，传输层落到具体链路。任何一层都不做"就近匹配"。

1
解析
取注册记录中的 device_type；缺失或非法立即抛 DriverNotFound，不回退。
2
实例化
按别名复用已有实例；首次创建时装载接口、型号、后端三项参数。
3
归一化
动作名转为能力键，保留原请求字符串用于结果追踪。
4
执行
查 ACTIONS 得到方法名，调用后组装统一结果结构。

实例状态机只有四个稳定态与一个异常态。开启失败不允许继续下发命令，关闭必须幂等。

状态进入条件允许动作退出
created构造完成，未建链读元数据、查能力open()
opened链路建立并完成识别全部已声明动作close()
busy长动作执行中仅状态查询动作返回
closed链路关闭，资源释放重新 open()—
error建链或协议失败仅 close() 与重开重开成功
约束驱动不得持有跨用例的全局状态；仿真实现与真机实现共用同一状态机，仅传输层不同。
04

开发视图

开发视图描述代码组织与构建顺序。运行期与开发期是两套目录，职责不重叠。

位置内容进入安装包
backend/drivers/factory.py、base.py、models.py、各设备实现是
backend/tps_runtime/用例执行器、结果收集是
sdk/ate_drivers/base / capabilities / transport / errors / family / kit / vendors / demos否
packaging/打包脚本、驱动门禁、安装器、启动器否（构建机）

驱动开发以厂商包为单位，包内固定四件：清单、实现、初始化、可选仿真数据。清单字段决定门禁能否通过。

文件职责关键约束
driver.json清单：键、版本、家族、入口、接口、型号、能力schema 固定为 ate.driver.manifest.v1
driver.py驱动实现，含 ACTIONS 与命令表能力键必须与 ACTIONS 键同名
__init__.py导出驱动类不放置副作用代码
simulate_command()仿真应答，供无设备开发输出必须确定，可复现

构建顺序固定六步，第 2.5 步为驱动门禁，不通过则整包终止。

1
前端构建
产出 web/，静态资源自包含。
2
后端装载
复制 backend 到 app/，删除运行期数据库与缓存。
3
驱动门禁
对 app/ 实测 8 类可实例化、动作可解析、注册库类型全解析。
4
运行时装填
嵌入 Python 与依赖，写入路径文件。
5
安装器封装
生成安装包与便携目录两种形态。
6
出包校验
校验文件清单、版本号、签名。
05

部署视图

部署形态为单机目录树，代码与数据物理相邻但职责分离。安装根目录记为 <RUNNER_HOME>。

<RUNNER_HOME>/
├─ app/                 运行期代码（整包替换）
│  ├─ drivers/          8 类驱动
│  ├─ tps_runtime/      用例执行
│  ├─ testresource/     种子数据（首次安装）
│  └─ ate.db            运行期生成
├─ web/                 前端静态资源
├─ runtime/             嵌入 Python 与依赖
├─ logs/                保留，不覆盖
├─ workspace/           保留，不覆盖
└─ updates/             installed_version.json
目录升级处理依据
app / web / runtime整体替换payload 目录清单
logs / workspace原样保留保留清单
testresource / ate.db / license.dat原样保留保留清单，按根目录解析

升级流程为"校验—备份—切换—确认"四段。任一段失败按整包回滚，不存在部分更新状态。

1
空闲校验
存在运行中任务则拒绝升级并提示，不进入后续步骤。
2
数据指纹
记录保留项的文件数与摘要，作为"数据未被冲掉"的判据。
3
备份与挂起
旧版本目录归档，写入待切换清单。
4
替换与确认
替换三个 payload 目录，写回版本号，重算指纹比对。
已知偏差当前 ate.db 与可写 testresource 位于 app/ 内，指纹解析已加 app/ 回退。目标态迁至 data/，使 app/ 成为纯只读代码。
