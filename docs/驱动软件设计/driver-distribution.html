01

为什么只保留在线分发

离线介质无法证明三件事：包从哪来、内容有没有被改过、是不是当前批准的版本。一旦允许 U 盘导入，签名校验就退化成"有个签名文件就行"，现场也无法区分正式包和临时改过的包。

分发结论

驱动只从受控在线仓库获取：仓库发签名索引，Runner 拉索引、验签、下载、校验、装包。

生产台架锁定精确版本，不自动追最新；回滚只切生效指针，不重新下载。

替代关系本文件取代旧版《驱动分发》中的多来源方案。旧版提到的 U 盘、共享盘、离线目录源全部作废，不再作为安装入口。
02

三种在线拓扑

拓扑按"包从哪个地址来"区分，校验流程完全一致。差异只在网络路径与审批方式，不在包格式。

拓扑做法适用注意
工位直连Runner 访问车间 HTTP 仓库的 index.json 与包单台或少量工控机断网时只读本地缓存，不静默降级
车间镜像车间镜像服务同步总部仓库，工位指向镜像多台 Runner、跨网段镜像只透传，不改包、不重签
MES 推送MES 按台架台账推送指定版本多产线、统一版本推送需审批记录，失败要回执

共同点

同一包格式、同一验签逻辑、同一状态文件、同一审计格式。

不同点

触发方式：手动检查、定时比对、MES 指令。

禁止

运行时无人值守自动升级生产台架。

03

索引与包

仓库根目录提供 index.json。索引本身要签名：Runner 先验索引，再信索引里的包哈希。

{
  "schema": "ate.driver.index.v1",
  "generated_at": "2026-10-18T10:00:00+08:00",
  "channel": "prod",
  "packages": [
    {
      "key": "tektronix-mso5",
      "version": "1.6.0",
      "api": "1.2",
      "min_platform": "1.0.0",
      "models": ["MSO54", "MSO56", "MSO58", "MSO64"],
      "url": "packages/tektronix-mso5-1.6.0.atepkg",
      "sha256": "…",
      "size": 48213,
      "signature": "…"
    }
  ]
}
约束原因
url 只能是相对路径或同域 HTTPS防止索引被指向任意下载源
同 key 可多版本，但 latest 只作展示生产不按 latest 升级
索引只追加，不覆盖历史条目要能解释"上周装的是哪个包"
包内必须含 SHA256SUMS 与 SIGNATURE索引哈希与包内哈希互为交叉校验
04

客户端行为

Runner 侧固定八步，任何一步失败都停在该步，不进入下一步。整个过程不修改正在生效的版本目录。

  1. 1

    读配置

    仓库地址、channel、受信公钥。配置变更要审计，不允许用例或 TPS 修改。

  2. 2

    拉索引

    下载 index.json 与 index.json.sig，验签通过才写入 drivers/.cache/。

  3. 3

    比对

    与 installed.json 比较，列出可升级、可回滚、缺失三类。

  4. 4

    下载

    只下选定版本，落到 .incoming/；支持断点续传但校验整包哈希。

  5. 5

    校验

    索引哈希、包内 SHA256SUMS、SIGNATURE 三者一致才继续。

  6. 6

    兼容与冲突

    检查 api、min_platform、型号归属；不通过即拒装。

  7. 7

    安装

    解包到 <key>/<version>/，写清单快照，按指令激活或仅登记。

  8. 8

    审计

    记录来源地址、操作者、包哈希、前后版本；失败也记录。

断网只读缓存索引，界面显示"离线，展示上次同步结果"，不发起请求，也不提供任何本地文件导入入口。
05

失败与回退

失败按发生位置分类，不按错误文案分类。每类都有确定的处置动作，避免现场"再试一次"。

失败点错误码处置对生产的影响
索引验签失败E_PKG_SIGNATURE弃用整份索引，保留上次缓存无，当前版本继续运行
包哈希不符E_PKG_HASH删除下载文件，禁止重试同一 URL无
包签名不符E_PKG_SIGNATURE丢弃并告警，要求重新发布无
契约不兼容E_PKG_COMPAT拒装，提示所需平台版本无
型号冲突E_PKG_CONFLICT拒装，列出归属 key无
装后派发失败E_PKG_LOAD自动回滚到上一 active 版本一次激活被撤销
回滚语义只改 active.json 指针，不重新下载、不重新解包。回滚耗时与包大小无关。
06

运维要点

事项要求
密钥私钥只在发布机；仓库与 Runner 只存公钥；轮换靠 key_id
通道prod / staging 独立索引，生产不读 staging
锁定台架锁定 key + version，升级是显式动作
保留至少 N-1 版本；卸载前检查台架锁
审计含操作者、来源、包哈希、前后版本，只追加
容量缓存按版本清理，不删除生效版本与锁定版本
