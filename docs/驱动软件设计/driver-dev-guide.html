01

适用范围与前置

本手册面向两类人：给新型号写驱动的开发者，以及在现场把驱动装上去、换回去的工程师。两者读同一份文档，但只需要看各自的章节——开发者从第 03 节开始，现场工程师直接看第 09 到 11 节。

前置项要求验证方式

SDK仓库内 sdk/ate_drivers，无需安装到 site-packagespython -m ate_drivers.kit.cli contract
仪器或仿真至少能在 simulate 模式跑通第 08 节门禁
契约版本ate.driver.api 1.2ATEDRV_API 常量
先读这一句驱动只负责「把动作翻译成协议」，不负责判定合格、不负责组织流程、不负责决定用哪个型号。
02

环境与目录

一个驱动包就是一个目录，目录名与 driver.json 的 key 一致。开发期放在仓库里，发布期打成 .atepkg，运行期解到 <RUNNER_HOME>/drivers/<key>/<version>/。

acme-psu-600/                 # 目录名 = key
├── driver.json               # 清单，必需
├── driver.py                 # 实现，类名与 entry 对应
├── __init__.py
└── assets/                   # 可选：命令表、校准数据

# 生成骨架
python -m ate_drivers.kit.cli new acme-psu-600 \
  --vendor Acme --model APS-600 --interface LAN --label "Acme 600W 电源"

允许

纯 Python 标准库实现；包内自带静态资源；同一包声明多个型号。

禁止

依赖第三方库（门禁 C15 会拦）；在包内读写注册库；import backend 或 tps_runtime。

03

最小可用驱动

下面是一个能通过门禁的最小实现。它声明了两个能力，用一条 SCPI 命令完成电压设置与回读，并在仿真模式下给出确定性应答。

# driver.py
from ate_drivers.base import InstrumentDriver
from ate_drivers.capabilities import capability

class AcmePsu600(InstrumentDriver):
    key = "acme-psu-600"
    family = "psu"
    label = "Acme 600W 电源"
    api_version = "1.2"
    sim_idn = "ACME,APS-600,0,1.0.0"

    ACTIONS = {"set_voltage": "set_voltage", "measure_voltage": "measure_voltage"}

    def set_voltage(self, volts: float) -> dict:
        self.write(f"VOLT {volts:.3f}")
        return {"value": volts, "unit": "V"}

    def measure_voltage(self) -> dict:
        raw = self.query("MEAS:VOLT?")
        return {"value": float(raw), "unit": "V"}
要点value 放主测量值，unit 必填（门禁 C08）；其余字段放 detail，由基类自动搬运。
04

清单字段

driver.json 是货架与运行时的唯一约定。字段分三档：缺失即拒收、缺失取默认、仅供展示。

字段要求校验规则示例
schema必填固定 ate.driver.manifest.v1ate.driver.manifest.v1
key必填小写字母开头，仅 a-z0-9._-acme-psu-600
version必填严格 x.y.z1.0.0
family必填必须属于已定义家族psu
api必填major 必须与平台一致，minor 不得高于平台1.2
entry必填module:ClassName，可导入driver:AcmePsu600
models必填非空、无重复（归一化后比较）["APS-600"]
interfaces可选LAN / SERIAL 组合["LAN"]
backends可选native / visa["native","visa"]
capabilities可选必须在家族能力表内["psu.set_voltage"]
simulate可选布尔，默认 truetrue
min_platform可选低于平台版本则拒装1.0.0
vendor / label可选仅展示，不参与派发Acme
改名代价key 是数据库里的 device_type，发布后不能改。要换命名，新增 key 并保留旧 key 一个发布周期。
05

能力与家族

家族决定"这台仪器应该会什么"，能力决定"这一版实现承诺了什么"。声明了但没实现，门禁 C04 直接拦下；实现了但没声明，上层 supports() 会返回 false。

家族典型能力不要放进该家族
scope取波形、读通道标度、触发配置、自动测量电源设压、负载拉载
dmm直流/交流电压电流、电阻、四线制波形采集
psu设压设流、输出开关、回读拉载与吸收
eload恒流/恒压/恒阻/恒功率、动态载供电
awg波形选择、频率幅度偏置、输出开关频谱分析
motion转速/位置设定、回零、状态查询模拟量采集
passive仅登记信息（夹具、工装）任何通讯动作
generic通用 SCPI 读写与状态查询家族专属语义

能力命名

<family>.<verb>_<object>，如 psu.set_voltage。动词用祈使式，不加 do、不加型号。

跨家族

一台设备同时是电源和万用表时，不要造"混合家族"。拆成两条设备记录，各用各的类型。

06

端点与传输

驱动不拼资源串，资源串由注册信息生成。驱动只声明自己支持哪种链路，运行时按 interface 选择传输实现。

链路注册字段资源串形态超时默认
LAN / SCPIhost、port(5025)TCPIP0::192.168.1.20::5025::SOCKET2 s 读，1 s 写
串口serial_port、baudrateASRL6::INSTR 或 COM6按波特率折算，最短 1 s
被动设备无无不建链路
常见错误在驱动里硬编码 IP 或 COM 口。这会让同一份驱动在第二条产线上失效，而且错误信息看起来像"仪器离线"。
07

动作实现规范

动作方法只做四件事：校验参数、拼协议、读写、返回结构化值。任何超出这四件事的逻辑都应上移。

规则要求违反后果
返回结构{"value": ..., "unit": "V"}，附加信息平铺门禁 C07 失败；上层无法统一取值
单位测量类动作必须带 unit报告缺单位，评审无法判断量级
错误抛 DriverError 子类，带稳定 code上层只能匹配中文，改文案就崩
超时不吞超时；让 DriverTimeout 冒泡用例误判为测量值异常
幂等设置类动作可重复执行且结果一致重试导致状态漂移
无状态假设不假设上次调用留下的仪器状态单步执行与连续执行结果不同
 
# 推荐：显式参数校验，错误码稳定
def set_current(self, amps: float) -> dict:
    if not (0 <= amps <= self.max_current):
        raise ConfigurationError(
            f"电流超出量程: {amps}A", detail=f"允许 0 ~ {self.max_current}A")
    self.write(f"CURR {amps:.4f}")
    return {"value": amps, "unit": "A"}
08

本地验证与门禁

上架前必须跑一致性检查。19 项全部通过才算"可装"，不是"能跑就行"。

python -m ate_drivers.kit.cli check acme-psu-600
python -m ate_drivers.kit.cli check acme-psu-600 --json > check.json
编号检查项常见不通过原因
C01类元数据完整缺 key / family / label
C02契约版本兼容api_version 写成 2.0
C03 / C04能力声明合法 / 均有实现声明了 scope.acquire_waveform 但没写方法
C05命令表完整ACTIONS 指向不存在的方法
C06仿真可执行全部能力仿真模式某动作抛异常
C07返回结构可序列化返回了对象或 bytes
C08测量项带单位只返回裸数字
C09错误可分类抛裸 Exception
C10 / C11会话可重入 / 安全退出close 后仍可写；异常时未释放
C12仿真可复现用随机数且无种子
C13实例互不干扰类级可变状态
C14旧动作别名有效弃用动作直接删掉
C15零第三方依赖import 了 numpy / pyvisa
C16弃用项有替代标注弃用但没给替代动作
C17型号可派发models 为空或与实现不符
C18 / C19连接方式 / 传输后端可声明声明了平台不支持的组合
判定报告 ok=false 时不允许打包上架；修完重跑，不要用 --force 绕过——那个参数只用于覆盖骨架文件。
09

打包、签名与上架

包是 zip，改名 .atepkg。打包顺序固定：先写清单，再算哈希，最后签名。签名覆盖 SHA256SUMS 的原始字节。

# 1. 打包（生成 driver.json / payload/ / SHA256SUMS）
python -m ate_drivers.shelf.package acme-psu-600 --out dist/acme-psu-600-1.0.0.atepkg

# 2. 签名（私钥只在发布机）
python -m ate_drivers.shelf.sign dist/acme-psu-600-1.0.0.atepkg \
  --key ~/.ate/keys/release.pem --key-id ate-prod-2026

# 3. 校验（装之前先自检）
python -m ate_drivers.shelf.verify dist/acme-psu-600-1.0.0.atepkg \
  --pubkey ~/.ate/keys/release.pub
错误码含义处置
E_PKG_LAYOUT根目录缺清单、路径越界、payload 为空重新打包，不要手工改 zip
E_PKG_MANIFEST清单字段缺失或格式非法按第 04 节逐字段核对
E_PKG_HASH文件与 SHA256SUMS 不一致包被改动过，重新打包
E_PKG_SIGNATURE签名无效或公钥不匹配确认 key_id 与受信公钥
E_PKG_COMPATapi 或 min_platform 不满足升级平台或改驱动
E_PKG_CONFLICT型号已被其他 key 声明改型号归属，不要并存
在线分发包只从受控 HTTP 仓库或 MES 推送获取；不接受 U 盘、聊天工具、邮件附件作为来源。下载后先验签，再进安装队列。
10

注册到测试台与 TPS 绑定

驱动装上不等于能用。设备记录必须显式选择类型，运行时才按这个类型精确取驱动。

  1. 1

    确认类型已注册

    GET /api/testbench/device-types 返回的清单里应出现 acme-psu-600；没有就是货架未激活。

  2. 2

    注册设备

    在注册页为每台设备选择类型，填型号与连接参数；第二步保存时会强校验，缺类型直接拒存。

  3. 3

    修正历史记录

    旧记录用 PATCH /api/testbench/{bench}/devices/{dev} 补 device_type，不要直接改 SQLite。

  4. 4

    TPS 声明别名

    device_config.psu = {"device_id": "rh-psu", "role": "psu"}，别名与类型无关，与设备记录对应。

  5. 5

    跑一条最小用例

    先 ctx.driver("psu").identify() 确认握手，再执行测量动作。

失败判据运行时报 E_NOT_FOUND 且信息为"未知设备类型"，说明类型没进注册表；报"设备未指定 device_type"，说明注册记录缺字段。两者处置不同。
11

发布、锁定与回滚

生产台架不允许"自动最新"。每个台架锁定精确的 key + version，升级是显式动作，回滚也是一步操作。

场景操作影响
新版本试跑装到货架但不激活，在试验台架手动激活生产台架不受影响
生产升级先在台架锁定新版本，再跑一遍首件失败可立即回滚
紧急回退rollback(key) 回到上一版本目录不动，只切生效指针
版本下线确认无台架锁定后卸载锁定的台架会阻止卸载

版本号

修协议 bug 升 patch；加动作升 minor；删动作或改语义必须升 major 并同步平台。

保留策略

至少保留 N-1 一个版本用于回滚，卸载前检查台架锁。

审计

安装、激活、回滚、卸载都写 audit.log，含操作者与包哈希。

13

提交前检查清单

下面十条全部打勾再提 PR。少一条都可能在上架阶段返工。

  • 19 项门禁全绿：cli check 返回 ok=true
  • 型号清单准确：models 与真实支持型号一致，无通配
  • 单位齐全：所有测量动作带 unit
  • 错误有码：每个失败路径抛带 code 的异常
  • 仿真可复现：同输入两次运行结果一致
  • 无第三方依赖：只用标准库
  • 不读注册库：连接参数只从 DeviceConfig 取
  • 清单版本正确：api=1.2，min_platform 明确
  • 包已签名：SIGNATURE 存在且可验
  • 回滚路径可用：上一版本仍在货架且未被卸载
