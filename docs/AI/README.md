## 二、三页要点

**第 1 页 概念、货架与设计预期**

- 定义：依附于测试装备运行的轻量应用，独立安装包分发，在设备侧完成单一增强功能；不进入 TPS 主流程、不改动测试基线。
- 首个实例：显微镜相机采图 → AI 识别标记位置与状态 → 输出判定与偏差量 → 供复核或后续工序引用。
- 与 TPS 的边界：运行方式（设备侧独立进程 vs 引擎调度）、版本变更（独立发布 vs 随基线回归）、失效影响（不阻断 vs 影响判定）。
- 先做助手的三条理由：不触碰基线、迭代可独立、风险可回退；并以生产数据决定是否并入 TPS。
- 货架字段：名称与能力、版本与变更、适用装备与相机型号、校验与签名、发布者。
- 下载与发布：用户自主检索下载，安装前强制校验；发布者上传经审核上架；助手启动检查版本、用户确认后更新，保留回滚。
- 设计预期：单件 ≤ 8 s、复核率 ≤ 10 %、漏检 ≤ 0.5 % / 误检 ≤ 3 %、单班 ≈ 2 人·时（初版目标，现场基线测定后校准）。

**第 2 页 设计方法、构建与接口**

- 构建五步：依赖锁定 → one-folder 打包 → 字节码加密与混淆 → 校验与签名 → 上架归档。
- 四组件：相机驱动（Basler pylon 8.0）、编排控制、算法服务（机器视觉库）、应用前端；另设结果存储分支。
- 接口契约：
  - IF-1 相机：`enumerate / open / apply / grab` → `Frame`
  - IF-2 检测：`detect(frame, recipe)` → `DetectionResult`，单帧超时 300 ms
  - IF-3 结果：`save / export / stats`，本地留存 ≥ 30 天
  - IF-4 前端：`onPreview / onResult / command`，预览降帧不影响节拍
