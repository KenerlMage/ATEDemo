# ATE 方案 PPT 设计与构建规范

本文件来自 ATE「驱动软件管理方案」deck（8 页，v1→v7）的实际迭代结论。所有数值都是被验证过的，不要凭感觉另起一套；要改先改这里，再改代码。

## 一、版面基线

| 项 | 值 |
| --- | --- |
| slide size | `LAYOUT_WIDE` = 13.333 × 7.5 in（16:9） |
| 左右页边距 M | 0.62 in |
| 内容宽 CW | 12.09 in（= 13.333 − 2×0.62） |
| 常用栅格 | 单栏 / 左右 5.5+6.36 / 三栏 3.7 等分 |
| 纵向起笔 | 标题 y=0.5，副标题 y=1.12，主体 y=1.78~2.02，底注 y≥6.1 |

纵向预算：主体区从 1.78 到 6.3 共 4.5 in 左右，超了就是拥挤。表格行高要先算总和再定起点，不要写完文字再挪。

## 二、色彩与字体（锁死）

```
PAPER  FDFDFC   页面底（暖白）
INK    141414   正文
SOFT   3A3A38   次级正文
MUTED  5F5E57   注释 / 图注
RULE   D6D3CB   细线（表格外框、分隔）
RULED  B5B0A6   稍深的线（强调框）
RED    8B0F1A   标题、唯一强调色
BLUE   1F4E79   关键词、栏目标签、表头
BLUE_T EDF2F8   浅蓝底（结论块、当前阶段）
GRAY_BG E7E6E1  副标题灰底
WASH   F4F3EF   弱底
```

- **字体只有一个：微软雅黑**。任何位置出现第二种字体都要修掉（用 `checkfont.py` 全片扫）。
- **强调色只有 `RED` 和 `BLUE`**。不要引入第三种彩色；不要用色条、色块做装饰，色彩只承担语义（红=标题/结论，蓝=关键词/结构标签）。

## 三、文字层级

| 角色 | 字号 | 颜色 | 规则 |
| --- | --- | --- | --- |
| 页标题 | 27pt bold | RED 8B0F1A | 陈述句，不用问句、不用动词短语 |
| 副标题 | 14pt | INK 141414 | 位于标题正下方，**灰底 GRAY_BG 的文本框**（不是纯文字），内容必须是一句完整陈述 |
| 栏目标签 | 9.4~9.6pt bold | BLUE | 如「层间接口与禁则（方案细节）」 |
| 正文 | 9~10.5pt | INK | 行距 1.2~1.32 |
| 表格正文 | 8.4~8.6pt | INK / 首列 BLUE / 禁则列 MUTED | 单元格 valign middle |
| 图注 / 底注 | 8.8pt | MUTED | 常作「数据来源 / 归属依据」一句话 |
| 元数据 | 8~8.5pt | MUTED | 版本、日期、编号 |

副标题必须是**陈述句**（讲结论），不是「本节介绍 X」这类导航语。示例：

- 好：「三类包的差别落在代码产出物、归档位置与下发链路上……」
- 差：「介绍三类包的差别」

## 四、图形与表格的硬约束

1. **只用 PPTX 原生 shape 与 native table**。禁止插图片当版式（唯一例外见第 2 条）、禁止把表格画成图片、禁止 SVG 贴图。
2. **唯一图片例外：需要识别真实装备时**（照片用于让读者认出是哪台设备）。此时：保持原始比例不裁不拉伸、加 0.75pt 细描边、8pt 图注写清包归属、不同设备并排时统一高度（如都 0.97 in），宽度按比例算。
3. **表格 `graphicFrame` 的 h 必须等于各行高之和**，否则 PowerPoint 里会被拉伸、行高失真。python-pptx 生成的表格常出现 `frame ≠ Σ rowH`，所以要跑一次修正（见「五」的 `fixtable`）。
4. **列宽之和必须等于表格 w**，且 w ≤ CW。三列表常见：`[1.3, 2.8, 2.56] = 6.66`（半幅）。
5. 表格行高公式（示例，5 数据行）：`rowH = [0.3, 0.66×5] = 3.6`，起点 2.02 → 结束 5.62，底部还留得下 0.9 in 的两段注释。
6. **不要页眉、不要页脚、不要页码**。信息放在副标题与底注里。
7. 竖排链路图用「矩形 + 向下箭头」：节点高 0.6、行距 0.86，箭头连 `y+0.6` 到 `y+0.84`；最后一个节点用 `BLUE_T` 填充表示当前对象。

## 五、构建流水线

pptxgenjs 出稿 → python-pptx 修正 → QA。顺序不能换。

```
node build_deck.js out.pptx          # 1. 生成（pptxgenjs，原生 shape/table）
python fixtable.py in out            # 2. 修正 graphicFrame 高度 = Σ行高
python post.py in out                # 3. 补 content-types / 关系、清临时部件
python tablefit.py out               # 4. 逐表核对 frame vs rows，打印 OK/不符
python check_vX.py out               # 5. 版式检查：overlap、图片数、表数量、标题
python verify_vX.py                  # 6. 规范检查：标题色、字体、页眉页脚残留
```

`fixtable.py` 的核心逻辑（三条）：

```python
# 1) 找到每张表的 a:graphicFrame，读 tbl 的行高
rows = [int(r.get("h")) for r in frame.iter(qn("a:tr")) if r.get("h")]
# 2) 把 frame 的 ext cy 改写成 sum(rows)，并同步 off 不变
frame.find(f".//{qn('a:ext')}").set("cy", str(sum(rows)))
# 3) 打印 frame vs rows，任何不等都要人工看
print(f"table {n}x{m} frame={cy/914400:.2f} rows={sum(rows)/914400:.2f}")
```

`post.py` 负责补 `[Content_Types].xml` 的 override（pptxgenjs 少写时会打不开）。它的输出形如：

```
ea-patched parts: 0 of 16
content-types: overrides=8 parts=8 sldIds=8
```

`overrides` 数量应等于 `parts` 与 `sldIds`，三者相等才算干净。

## 六、QA 闸门（每次出片都跑）

- [ ] `tablefit` 全部 `frame == rows`，没有 OVERFLOW 提示
- [ ] `QA: clean`（overlap 检查：任意两个 shape 的矩形不得相交，表格与注释允许贴合但不重叠）
- [ ] `slides: N` 与设计页数一致
- [ ] 标题全部 27pt + `8B0F1A`
- [ ] 全片只有 `微软雅黑`
- [ ] `--- header/footer residue --- none`
- [ ] 图片：张数正确、坐标与设计一致、宽高比 = 原图比例
- [ ] content-types `overrides == parts == sldIds`

本机没有 PowerPoint / LibreOffice 时**无法导出像素预览**，只能程序化 QA + 坐标核对。此时必须把「哪些结论是几何核对得出、哪些是目视确认」分开说，不要把几何核对说成「看过效果」。

## 七、内容写法

- 标题陈述结论，不用「关于……」「……介绍」。
- 每页一个判断，判断放标题；证据放表格；边界与例外放底注。
- 禁止口语化：「我们其实」「大概」「比较好」；改成可判定的表述。
- 数字带单位、带口径（1.72 × 0.97 in、13/13、14168 B、sha256 前 8 位）。
- 不写「本节将介绍」，直接写内容。
- 一页只允许一个「强调」动作：要么红标题 + 蓝标签，不要再叠第三层。

## 八、可复用页面模板

| 模板 | 结构 |
| --- | --- |
| 背景页 | 标题「问题背景」+ 副标题陈述现状 + 3~4 条事实 + 一条底线结论 |
| 分类页 | 三栏（每栏：名称 + 判据 + 优势）+ 对比表 + 可选设备照片带 + 归属依据底注 |
| 代码方案页 | 一张 N×4 表（维度 / 三类包各一列）+ 下方 1~2 条粒度与回滚注释 |
| 逻辑视图页 | 左四层方块（自上而下）+ 右解析步骤表 + 适用范围声明 |
| 连接页 | 左：竖向链路 5 节点（属性→lock→解析结果→实例→调用）；右：层间接口与禁则表 |
| 开发视图页 | 左：代码树（等宽字体、层级缩进 0.26 in）；右：开发范围表 + manifest 小块 |
| 仿真定义页 | 左：定义 / 仿什么 / 不仿什么；右：实现要素表 |
| 推进策略页 | 整页 5×5 表（阶段 / 周期 / 主要工作 / 交付物 / 准入判据）+ 已完成与待完成各一行 |

## 九、环境坑（Windows + PowerShell）

1. **不要用 bash heredoc**（`<<'PY'`）：PowerShell 会报「重定向运算符后面缺少文件规范」。写成 `.py` 文件再执行。
2. **`Get-Content` / `Set-Content` 往返会破坏 UTF-8 中文**（曾把构建脚本里的中文标签写成乱码）。要改文件用 python `io.open(..., encoding="utf-8")`。
3. **`Set-Content -Encoding utf8` 会写 BOM**，Node/Python 读 JSON 时报 `Unexpected UTF-8 BOM`。JSON 一律用无 BOM 写入。
4. **带引号或正则的 `python -c "..."` 会被 PowerShell 拆坏**，尤其含 `<`、`>`、`|`、`$_`。改用脚本文件。
5. **跨盘读写**：D 盘文件先 `Copy-Item` 到工作目录再读；构建输出再 `Copy-Item` 回去。
6. **pptxgenjs 的 `addTable` 的 `rowH` 是每行英寸值数组**，`colW` 同理；`margin` 用英寸；`border: {pt: 0.5, color}`。
7. 改版要**新建 `build_deckN.js`**，不要原地改旧脚本：旧脚本是回滚基线，且能对比两版差异。

## 十、新增或改版一页的流程

1. 用一句话写出这页的判断（会成为标题）。
2. 选模板（第八节），确定纵向预算：主体高度 = Σ(表行高) 或 Σ(节点高 + 间距)。
3. 复制上一版 build 脚本为新版本，只加这一页，页序与后续页码重排。
4. 跑完整流水线（第五节），过 QA 闸门（第六节）。
5. 复制到交付目录，同步 HTML 说明页的小节编号与目录。
6. 提交时把 PPTX、HTML、图片素材一起提交，临时脚本不进仓库。
